### 0.3 现状诊断（本次升级要解决的问题）

以下问题均来自对当前代码的核查，每一条都在后续章节有对应解法。

1. **强调色与语义色冲突**。浅色主题强调色 `#16a34a`（绿）与「正常」色 `#15803d`（绿）几乎同色；深色主题「正常」直接复用强调色香槟金 `#e0b97b`。用户无法区分「这里可以点」与「这里状态正常」。解法见第二章 2.1.3。
2. **离线被当作风险的第五级**。`data-risk="offline"` 与 normal / warn / alarm / crit 并列在同一条色阶上，灰色被排在红色之后，值班人员会误读。解法见第二章 2.1.4 与第四章 4.2。
3. **样式分散在三处**。`static/app.css`（2124 行，前 1485 行为深色遗留，第 20 节为白色主题覆盖层）、`_shell.html` 内联 `<style>`、各页面内联 `<style>`。同一颜色存在 `var(--x, 兜底值)` 的两处取值。解法：本规范的 token 成为唯一真相，见第八章实施顺序。
4. **深色时代的装饰残留**。如 `--grid` 网格底纹、`--accent-glow` 发光、`--sheen` 内高光、香槟金滚动条。解法见第六章。
5. **固定画布缩放遗留**。`--s-top` / `--s-bottom` 等大屏骨架尺寸服务于已废弃的 1920×1080 缩放方案。解法见第三章。
6. **字号随视口缩放**。`alarms.html:36` 与 `device.html:35` 用 `--pg-s` 把字号、间距在 1440px 到 2592px 之间线性放大到 1.25 倍，导致同一组件在不同页面、不同屏幕上字号不同。解法见第三章 3.1.4。

- 「浅 / 深」分别指 `data-theme="light"` / `data-theme="dark"` 下的取值。

## 一、设计理念

### 1.1 核心理念（一句话）

**像一台校准过的测量仪器：读数精确、状态诚实、界面安静，只有结构出了问题时才发出声音。**

理由：桥梁监测的使用者是工程师和值班人员，他们要的不是「看起来很厉害」，而是「看一眼就知道桥现在安不安全，并且相信这个判断」。仪器的气质是这个场景最准确的隐喻：游标卡尺、示波器、全站仪的界面从不装饰，每一道刻线都有意义，读数永远对齐，报警永远醒目。界面平时越安静，报警出现时就越不需要靠特效去吸引注意。

### 1.2 设计原则

#### 原则一：颜色即语义，静默即正常

颜色只承担两种职责：**风险等级**（预警 / 报警 / 严重报警）和**交互可用性**（钢蓝强调色）。除此之外，界面全部由中性灰阶构成。

- 「正常」状态使用低饱和绿，且只出现在状态点、等级标签等小面积元素上，不铺大面积底色。
- 全屏中饱和度最高的元素，永远是当前最严重的那条报警。
- 不存在「为了好看」而上的颜色。

理由：值班人员的注意力是稀缺资源。如果平时界面就五颜六色，真正的红色报警会被淹没。让「正常」显得平淡，是让「异常」显得醒目的前提。这也直接解决了 0.3 第 1 条的强调色冲突问题。

#### 原则二：诚实表达不确定性

数据不可信时，界面必须明确表达「不知道」，而不是给出一个看似确定的状态。

- 离线时数值显示为 `--`，风险指示器切换为「未知」样式（中性灰 + 虚线边框 + 斜线纹理），绝不沿用离线前的最后一次风险色。
- 模拟模式下，「模拟」标识常驻可见，不得被收起或弱化到难以辨认。
- 数值的精度与传感器精度一致，不显示无意义的小数位。

理由：监测系统最危险的失败不是报错，而是「看起来一切正常，其实早就断线了」。这是 D7 决策的设计依据，也是用户信任系统的基础。

#### 原则三：结构即秩序

视觉层级由**字号、字重、间距、对齐**四个手段建立，不依赖阴影、渐变、发光、圆角卡片堆叠。

- 一切元素落在 4px 基线网格上。
- 面板之间以 1px 发丝边分隔，而不是以投影悬浮。
- 同一层级的元素，左边缘必须严格对齐。
- 数字一律等宽（tabular-nums），同列数字小数点对齐。

理由：瑞士国际主义平面设计的核心主张是「网格与字体自身足以建立秩序」。工程图纸也是同样的逻辑：图框、标题栏、尺寸线，全靠线条和字来组织。用阴影和卡片堆出来的层级，在信息密集时会变成噪音。

#### 原则四：数据墨水比优先

每一个像素都要传达信息，不传达信息的像素删掉。

- 图表去除冗余网格线（仅保留水平参考线，且为最弱灰阶），去除边框，去除背景填充。
- 坐标轴标签只保留必要刻度。
- 图例能直接标注在曲线末端的，就不另设图例框。
- 3D 场景中不加入装饰性粒子、光晕、扫描线。

理由：这是 Edward Tufte 的数据可视化基本原则。对于需要快速判读趋势的工程人员，任何非数据元素都会延长判读时间。

#### 原则五：一套系统，七个页面

所有页面共享同一套 token、同一套组件、同一个骨架。页面之间的差异只能来自内容和布局，不能来自各自的配色或组件变体。

- 页面内联 `<style>` 只允许写布局（栅格位置、区域尺寸），不允许写颜色、字号、圆角、阴影的字面量。
- 同一个组件（如按钮、表格、状态标签）在任何页面外观一致。
- 浅色与深色是同一套系统的两种明度映射，不是两套设计。

理由：0.3 第 3 条指出当前样式散在三处且存在重复取值，这是长期迭代后各页面「各自为政」的结果。这条原则是本次升级能否持久的关键：如果没有它，下一轮迭代又会开始漂移。

### 1.3 气质坐标

为避免对「精密、工程感」产生不同理解，用以下对照明确定位：

| 维度 | 本系统是 | 本系统不是 |
|---|---|---|
| 参照物 | 示波器、全站仪、Grafana、Linear、Vercel Dashboard | 智慧城市指挥大屏、游戏 HUD、发布会 PPT |
| 色彩 | 中性灰阶为主体 + 一个钢蓝 + 三个风险色 | 蓝紫渐变、霓虹青、多色彩虹 |
| 层级 | 发丝边、字重对比、留白 | 投影、毛玻璃、发光描边 |
| 密度 | 高密度、结构化、可扫读 | 大留白、大标题、少量巨型数字 |
| 动效 | 仅用于状态变化的反馈，时长 ≤400ms | 循环装饰动画、粒子、扫描线 |
| 情绪 | 冷静、可信、克制 | 炫酷、激动、未来感 |

## 二、设计系统（Design Tokens）

本章定义的每一个 CSS 变量都是全站唯一真相。所有页面、组件、ECharts 配置、3D HUD 都只能引用这里的变量，不得出现颜色、字号、间距、圆角、阴影、时长的字面量。

唯一例外是 ECharts 与 Three.js 的 JS 配置。它们无法直接使用 CSS 变量，必须在运行时读取根元素的计算样式，取得同名变量的值；不得在 JS 里另抄一份色值。具体做法见第四章 4.4、4.5 与第七章。

### 2.0 命名约定

- **语义命名，不以色相命名**。写 `--text-secondary`，不写 `--gray-600`。理由：深浅两套主题下同一语义对应不同色值，以色相命名的变量在切换主题后就会「说谎」。
- **前缀分组**：`--bg-*` 背景，`--border-*` 边框，`--text-*` 文字，`--accent-*` 强调色，`--risk-{级别}-*` 风险等级色，`--trust-*` 数据可信度色，`--chart-*` 图表，`--twin-*` / `--hud-*` 3D 场景与覆盖层，`--font-*` 字体栈，`--fs-*` 字号，`--lh-*` 行高，`--fw-*` 字重，`--sp-*` 间距，`--radius-*` 圆角，`--shadow-*` 阴影，`--z-*` 层级，`--dur-*` 时长，`--ease-*` 缓动。
- **风险级别后缀固定为** `normal` / `warn` / `alarm` / `crit`。它们与后端场景键 `normal` / `warn` / `alarm` / `critical`、以及现有 `data-risk` 取值一一对应（`critical` 在 CSS 侧简写为 `crit`，与现有代码一致）。
- **主题挂载方式**：两套取值分别挂在根元素的 `[data-theme="light"]` 与 `[data-theme="dark"]` 上；`:root` 本身持有浅色取值，保证未设置主题属性时渲染为浅色（D1）。
- 旧变量名（`--bg`、`--panel`、`--muted`、`--accent`、`--ok` 等）的处置见第八章映射表。

### 2.1 色彩系统

本节所有对比度均按 WCAG 2.1 相对亮度公式实算，不是估算。

#### 2.1.1 背景层级

背景分五级。界面的层级感主要由这五级背景加 1px 发丝边建立，而不是靠阴影。

| 变量 | 浅色 | 深色 | 层级 | 使用场景 |
|---|---|---|---|---|
| `--bg-canvas` | `#F4F5F7` | `#0B0C0E` | L0 页面底 | `body` 背景；主内容区背景；3D 画布清屏色（与 `--twin-clear` 同值） |
| `--bg-surface` | `#FFFFFF` | `#121316` | L1 面板 | 侧栏、顶栏、所有面板与卡片、表格主体、表单容器 |
| `--bg-subtle` | `#F9FAFB` | `#17181B` | L1.5 面板内分区 | 表格表头行、需要与内容区分的面板标题栏、键值行的偶数行 |
| `--bg-sunken` | `#EDEFF2` | `#0E0F11` | L-1 凹陷 | 只读输入框、进度条与阈值条的轨道、骨架屏占位块、原始串口帧显示区 |
| `--bg-raised` | `#FFFFFF` | `#1C1E22` | L2 浮层 | 下拉菜单、用户菜单、悬浮提示（深色主题）、对话框、抽屉 |

交互态背景，叠加在 L1 之上使用：

| 变量 | 浅色 | 深色 | 使用场景 |
|---|---|---|---|
| `--bg-hover` | `#F1F3F5` | `#1A1C20` | 导航项、表格行、列表项、次要按钮、菜单项的悬停态 |
| `--bg-active` | `#E9ECEF` | `#1F2228` | 上述元素的按下态 |
| `--bg-selected` | `#EBF1FA` | `#18233A` | 当前选中项：导航激活项、表格选中行、分段控件激活项。与 `--accent-soft` 同值 |
| `--bg-scrim` | `rgba(22, 24, 29, 0.40)` | `rgba(0, 0, 0, 0.60)` | 移动端抽屉遮罩、对话框遮罩 |

理由：

- 浅色主题 L0 用浅灰、L1 用纯白，面板自然「浮」在灰底上，不需要阴影就有层次。Linear 浅色模式和 Vercel Dashboard 都是这个做法。
- 浅色下 `--bg-raised` 与 `--bg-surface` 同为白色，L1 与 L2 靠阴影区分，因为浅色下阴影清晰可见。深色下阴影几乎看不见，所以浮层必须比面板更亮一级（`#1C1E22`）。这是深色主题建立层级的唯一可靠手段。
- `--bg-sunken` 在两套主题下都比 L1「更远」：浅色更灰，深色更黑。它表达「这里是容器内部，只读或不可直接操作」。
- 所有背景都是中性灰，不带任何蓝紫或暖金倾向。旧深色主题的底色带暖金调，会和预警的琥珀色互相干扰（0.3 第 4 条）。中性灰让风险色成为画面里唯一有色相的东西。

#### 2.1.2 边框与分隔线

| 变量 | 浅色 | 深色 | 使用场景 |
|---|---|---|---|
| `--border-subtle` | `#E6E8EB` | `#1F2125` | 面板内部分隔：表格行线、键值行之间、列表项之间、面板标题栏下沿 |
| `--border-default` | `#DCDFE3` | `#2A2C31` | 面板与卡片外框、侧栏右边线、顶栏下边线、指标带单元格之间的竖线 |
| `--border-strong` | `#C8CCD2` | `#33363C` | 次要按钮边框、分段控件外框、浮层外框（深色主题浮层必须有边框）、表头下沿 |
| `--border-control` | `#8F959E` | `#60656E` | 表单控件边框：输入框、下拉选择框、复选框、单选框 |
| `--border-focus` | `#3A68AD` | `#7FA2DA` | 键盘焦点环；输入框聚焦时的边框。与 `--accent-default` 同值 |

所有边框宽度统一为 1px，焦点环为 2px。不存在 0.5px 或 1.5px 的边框。

理由：

- 边框分四级，是因为「面板之间的边界」「面板内部的分隔」「可交互控件的边界」三者传达的信息完全不同，必须让眼睛一眼分辨。
- `--border-control` 刻意比面板边框重得多。浅色 `#8F959E` 对白底 3.02:1，深色 `#60656E` 对 `#121316` 3.17:1，都满足 WCAG 非文本对比度 3:1 的要求。表单控件必须让人一眼看出「这里可以输入」；面板边框只是区域划分，不需要达到这个标准。
- 深色主题的边框只比背景亮约 1.3 到 1.9 倍，刻意保持极细微。Linear 深色模式的精密感正来自这种「几乎看不见、但确实存在」的发丝边。

#### 2.1.3 主强调色（钢蓝）

| 变量 | 浅色 | 深色 | 使用场景 | 对比度 |
|---|---|---|---|---|
| `--accent-default` | `#3A68AD` | `#7FA2DA` | 链接文字、焦点环、输入框聚焦边框、导航激活项左侧指示条、分段控件激活项文字 | 浅：对白 5.58:1；深：对 `#121316` 7.15:1 |
| `--accent-fill` | `#3A68AD` | `#3F6BB0` | 主按钮背景；复选框与开关的选中填充 | 白字其上：浅 5.58:1，深 5.33:1 |
| `--accent-fill-hover` | `#2F5996` | `#4673B8` | 主按钮悬停 | 白字其上：浅 7.02:1，深 4.77:1 |
| `--accent-fill-active` | `#284E87` | `#3762A5` | 主按钮按下 | 白字其上：浅 8.30:1，深 6.08:1 |
| `--accent-soft` | `#EBF1FA` | `#18233A` | 选中态背景；文本选区背景 | 强调色文字其上：浅 4.91:1，深 6.03:1 |
| `--accent-border` | `#A9C0E3` | `#2E4670` | 选中态卡片的描边（如设备页当前选中的数据源卡片） | 装饰性，无要求 |
| `--text-on-accent` | `#FFFFFF` | `#FFFFFF` | 主按钮文字、选中复选框内的勾 | 见上 |

色相统一为 HSL 约 216°，浅色饱和度约 50%，深色约 55%，均属低饱和。

使用规则（强制）：

1. **强调色只表达「可交互」或「当前选中」，永远不表达状态。** 正常状态用 `--risk-normal-*`，不得用强调色替代。
2. **一个视口内，用 `--accent-fill` 实心填充的元素最多 1 个**，即每屏最多一个主按钮。主按钮代表「这一屏最推荐的操作」，有两个就等于没有。
3. 强调色不得用于：大面积背景、面板顶部色条、标题文字、图表数据线、3D 材质。
4. 禁止任何形式的强调色渐变，包括同色相不同明度的渐变。
5. **焦点环**：所有可聚焦元素在 `:focus-visible` 时显示 2px `--border-focus` 实线外环，与元素外沿相距 2px，外环圆角等于元素圆角加 2px。鼠标点击不显示焦点环，只有键盘导航时显示。

理由（为什么是钢蓝、为什么低饱和）：

- 语义色已经占用了绿（正常）、琥珀（预警）、橙（报警）、红（严重报警）、灰（离线/未知）。唯一不会和任何状态混淆的色相是蓝。这直接修正了 0.3 第 1 条：旧浅色强调绿 `#16a34a` 和正常绿 `#15803d` 同色；旧深色的强调香槟金 `#e0b97b` 被直接拿来当正常色。
- 低饱和是为了避开「科技蓝」的廉价感。高饱和的 `#2563EB`、`#3B82F6` 是通用后台模板和 AI 生成界面的默认色，第六章明令禁止。钢蓝偏灰，接近工程蓝图和钢结构涂装的色调，与桥梁题材天然契合。
- 深色主题把文字强调色 `#7FA2DA` 和填充强调色 `#3F6BB0` 分开设置：深底上的链接文字必须足够亮才能读清；按钮填充如果也那么亮，白字就会失去对比度。

#### 2.1.4 风险等级色（四级）与数据可信度色

按 D7，**风险等级只有四级**：正常、预警、报警、严重报警。离线不是第五级风险，而是「数据可信度为不可信」，此时风险等级显示为「未知」。因此色板分两组：风险等级组（四色有序）和可信度组（中性灰，无色相）。

每个状态提供以下变量：

- `-main`：图形元素色。用于状态点、色条、图标、3D 测点、图表超限区段、进度条填充。要求对 L1 背景 ≥3:1。
- `-bg`：浅底色。用于状态标签底色、报警行的未处理底色、新行入场高亮。
- `-text`：文字色。用于写在 `-bg` 或 L1 背景上的状态文字。要求对两者均 ≥4.5:1。
- `-border`：描边色。用于状态标签边框、风险指示器外框。
- `-solid-text`：写在 `-main` 实心填充上的文字色。只有严重报警使用实心填充。

使用规则（强制）：

**规则 1：四级风险的视觉强度严格递增，升级的不只是颜色，还有表达方式。**

| 级别 | 状态点 | 状态标签 | 行级与面板级表达 | 动效 |
|---|---|---|---|---|
| 正常 | 8px 实心圆，`-main` | 无底色，仅 `-text` 文字加前置状态点 | 无 | 无 |
| 预警 | 8px 实心圆，`-main` | `-bg` 底 + `-text` 文字 + 1px `-border` 描边 | 报警行左侧 2px 色条 | 无 |
| 报警 | 8px 实心圆，`-main` | 同预警 | 报警行左侧 3px 色条；未处理时整行 `-bg` 底 | 无 |
| 严重报警 | 8px 实心圆，`-main` | **实心**：`-main` 底 + `-solid-text` 文字，无描边 | 报警行左侧 4px 色条；未处理时整行 `-bg` 底 | 未处理时状态点脉冲（见 2.6.4） |

理由：只靠颜色区分等级，色觉障碍者（约占男性 8%）无法分辨橙与红、琥珀与绿。「色条宽度递增 + 标签从描边变实心 + 是否有动效」三重冗余编码，保证任何人都能读出等级高低。同时符合原则一：正常态最安静，只有一个小绿点。

**规则 2：未知状态不使用任何风险色。** 数值显示 `--`；状态标签用 `--trust-unknown-bg` 底 + `--trust-unknown-text` 文字 + 1px **虚线** `--trust-unknown-border` 描边（虚线段 3px、间隔 2px）；色条与指示器使用斜线纹理。理由：在工程制图中，虚线和斜线通用于表示「隐藏、不确定、待定」，无需学习就能理解；同时确保离线在视觉上不处于四级色阶的任何位置（D7）。

**规则 3：风险色禁止用于**装饰、标题、普通按钮、与阈值无关的图表数据线。唯一例外是危险按钮（如「清空数据」），使用 `--risk-crit-*`，因为这类操作的后果和严重报警同样不可逆。

**规则 4：颜色变化必须伴随文字。** 任何用颜色表达等级的地方，8px 范围内必须有等级文字，或有形状不同的图标。

**规则 5：`data-risk` 与中文标签的对应固定，不得改写或缩写。**

| `data-risk` | 显示文字 | 变量前缀 |
|---|---|---|
| `normal` | 正常 | `--risk-normal-*` |
| `warn` | 预警 | `--risk-warn-*` |
| `alarm` | 报警 | `--risk-alarm-*` |
| `crit` | 严重报警 | `--risk-crit-*` |
| `offline` | 风险等级显示「未知」，可信度显示「离线」 | `--trust-unknown-*` |

理由（色值选取）：

- 浅色主题四个 `-main` 都取中等明度，保证 8px 状态点在白底上清晰可辨；`-text` 再加深一档，达到正文级 4.5:1。旧浅色主题直接拿深色（如 `#15803d`）当图形色，状态点在小尺寸下发黑、彼此难辨。现在图形色和文字色分离，解决了这个问题。
- 预警刻意选偏棕的琥珀 `#B7791F`，不用纯黄。纯黄在白底上对比度不到 2:1，无法用于任何图形元素。
- 深色主题四色整体提亮并略降饱和，避免近黑底上的霓虹感（第六章禁止霓虹）。`#EF5A5F` 比纯红柔和得多，对深底仍有 5.57:1。
- 正常色选偏蓝的海绿（色相约 150°），不用偏黄的草绿，以拉开与预警琥珀的色相距离（约 110°）。

1. 一个组件内最多出现三级文字（primary、secondary、tertiary）。
2. **数据数值永远用 `--text-primary`，不随风险等级变色**；风险由相邻的状态点、色条、标签表达。理由：如果数值本身变红，数字的可读性会随状态恶化而下降，而恰恰是最危险的时候最需要读清数字。唯一例外：风险指示器内的「风险等级」文字本身使用风险色（见第四章 4.2）。
3. 占位符用 `--text-tertiary`，不得用禁用色。浅色主题的禁用色只有 2.36:1，用作占位符会看不清输入提示。
4. 大面积正文不得使用纯黑 `#000000` 或纯白 `#FFFFFF`（`--text-on-accent`、`--text-inverse` 小面积使用除外）。纯黑对纯白 21:1，长时间阅读刺眼；`#16181D` 已有 17.76:1，足够且更柔和。

理由：

- **主数据线用墨色而不是彩色**，是本规范最重要的决策之一。按原则一，颜色只表达语义；一条普通的应变曲线没有「状态」，它就是数据本身，应该像示波器扫描线、图纸墨线一样，是画面中最重的中性元素。曲线超过阈值时，超限区段才分段着色为风险色（规则见第四章 4.5）。这时颜色才有意义：这一段出问题了。

- 不画竖直网格线：时间轴上的竖直网格对判读应变趋势没有帮助，只增加墨水。

#### 2.1.8 深色模式下的层级关系

浅色与深色是**同一个层级模型的两种明度映射**，不是两套设计。

| 层级 | 语义 | 浅色怎样建立 | 深色怎样建立 |
|---|---|---|---|
| L-1 凹陷 | 只读、轨道、占位 | 比 L1 更灰 `#EDEFF2` | 比 L1 更黑 `#0E0F11` |
| L0 页面底 | 承载一切 | 浅灰 `#F4F5F7` | 近黑 `#0B0C0E` |
| L1 面板 | 内容主体 | 纯白 + 1px `#DCDFE3` 边框，**无阴影** | `#121316` + 1px `#2A2C31` 边框，**无阴影** |
| L1.5 面板内分区 | 表头、标题栏 | `#F9FAFB`，比 L1 微灰 | `#17181B`，比 L1 微亮 |
| L2 浮层 | 菜单、提示、对话框 | 纯白 + **阴影**：阴影是主要区分手段 | `#1C1E22` + 1px `#33363C` 边框 + 阴影：**明度提升**是主要区分手段，阴影只是辅助 |

核心规律：

1. **浅色主题里，层级越高越靠阴影区分；深色主题里，层级越高越亮。** 深色下「越近越亮」符合物理直觉：离光源越近的面越亮。Material Design 和 Linear 的深色模式都遵循这一点。
2. 深色主题 L0、L1、L2 之间的明度阶梯约为每级 +4% 到 +6% 亮度。阶梯太小，层级不可辨；太大，界面会发灰，失去深色的沉稳感。
3. **深色主题禁止用纯黑 `#000000` 作为任何背景。** 纯黑上的浅色文字会产生光晕，而且无法建立「比底更暗」的凹陷层。
4. 风险色在深色下整体提亮约 25% 到 35%，降饱和约 10%，保证对比度的同时避免霓虹感。
5. 浅色主题使用纯中性灰阶；深色主题的灰阶蓝通道比红通道高 2 到 5 个单位（如 `#121316`），带极轻微的冷调。纯中性的深灰在液晶屏上容易显得偏暖发棕，轻微冷调可以抵消这种观感，也更贴近钢结构的题材。偏差控制在人眼无法察觉为「蓝色」的范围内。

打包要求（D5）：

- Inter 打包 400、500、600、700 四个字重的 woff2 文件，放在 `static/fonts/`，用 `@font-face` 本地引用，`font-display: swap`。
- 只打包拉丁子集：U+0000–00FF（基本拉丁与拉丁补充，含 `°` `±` `×`）、U+0391–03C9（希腊字母，含 `μ` `ε`）、U+2000–206F（通用标点）、U+2070–209F（上下标）、U+2100–214F（字母式符号，含 `℃`）、U+2212（减号）。每个字重约 25 到 35KB，四个字重合计不超过 150KB。
- 用 `unicode-range` 限定 Inter 只渲染上述区段，中文字符自动落到后面的系统中文字体。
- 禁止引用任何字体 CDN。断网可用是硬性要求（`_shell.html` 头注释中的「离线红线」）。

理由：

- Inter 排第一，让数字、英文与符号（`%`、`×`、`±`、`−`、`ESP32`、`CH1`）全部由 Inter 渲染。Inter 的等宽数字专为界面设计，`1` 和 `7`、`0` 和 `8` 在小字号下的辨识度远高于微软雅黑自带的数字。数字是这个系统的主角，必须在所有平台上字形一致、宽度一致。
- 中文交给系统字体：Windows 现场电脑必有微软雅黑，Mac 必有苹方。思源黑体每个字重约 8MB，子集化后仍超过 1MB，对现场工控机而言代价太高，视觉收益却有限。
- `"Microsoft YaHei UI"` 排在 `"Microsoft YaHei"` 之前：UI 版行距更紧凑，专为界面设计，12 到 14px 下更清晰。

#### 2.2.2 字号阶梯

正文基准 14px，共 8 级，每级用途唯一。

| 变量 | 字号 | 行高变量 | 行高 | 用途 |
|---|---|---|---|---|
| `--fs-2xs` | 11px | `--lh-2xs` | 16px | 图表坐标轴刻度；3D 测点标签的单位；版本号脚注。**只用于数字、英文和符号** |
| `--fs-xs` | 12px | `--lh-xs` | 16px | 指标标签（如「当前应变指标」）；表头；时间戳；状态标签文字；表单帮助文字；面包屑；导航提示气泡 |
| `--fs-sm` | 13px | `--lh-sm` | 20px | 表格单元格；报警原因；键值行；下拉菜单项；HUD 按钮文字；悬浮提示 |
| `--fs-md` | 14px | `--lh-md` | 20px | **默认正文**；按钮文字；输入框文字；导航项；面板标题；报警规则名 |
| `--fs-lg` | 16px | `--lh-lg` | 24px | 区块标题（设置页分组标题、对话框标题）；移动端输入框文字 |
| `--fs-xl` | 20px | `--lh-xl` | 28px | 页面标题（顶栏中的「实时趋势」「报警中心」等）；登录页系统名称 |
| `--fs-2xl` | 24px | `--lh-2xl` | 28px | 指标带与指标卡中的次要数值（报警阈值、变化率等） |
| `--fs-3xl` | 32px | `--lh-3xl` | 36px | 每页唯一的主读数（「当前应变指标」数值）与风险等级文字 |

规则：

1. **每个页面 `--fs-3xl` 最多出现 2 处**：主读数和风险等级。最大字号代表「这一页最重要的东西」，出现多处就失去焦点。
2. **不使用 32px 以上的字号**，旧方案的 `--fs-hero: 44px` 废弃。超大数字是「大屏炫技」的典型手法；32px 在 1920 宽的屏幕上，2 米外仍能清晰读取，已经足够。
3. **单位跟随数值时，单位取数值字号的约一半**（就近取阶梯值）：32px 数值配 14px 单位，24px 配 12px，14px 配 12px，13px 配 11px。单位用 `--text-tertiary`，与数值间距 4px，基线对齐。单位是读数的必要信息，但不是视线焦点。
4. **中文最小字号 12px**，不得对中文使用 11px。微软雅黑在 11px 下笔画会粘连，「警」「测」「器」这类复杂字无法辨认。
5. 移动端（≤768px）阶梯不变，只有两处例外：输入框文字强制 16px（防止 iOS 聚焦时自动缩放页面）；导航项文字 15px（沿用 `_shell.html` 现有移动端规则）。

#### 2.2.3 字重规则

| 变量 | 字重 | 使用场景 |
|---|---|---|
| `--fw-regular` | 400 | 正文、表格单元格、报警原因、说明文字、输入框文字、键值行的值 |
| `--fw-medium` | 500 | 指标标签、表头、导航项、按钮文字、状态标签、HUD 按钮、键值行的键 |
| `--fw-semibold` | 600 | 页面标题、面板标题、区块标题、对话框标题、报警规则名、风险等级文字、`--fs-2xl` 次要数值 |
| `--fw-bold` | 700 | 只用于 `--fs-3xl` 主读数数值 |

规则：

1. 一个组件内最多出现两种字重。
2. 禁止使用 300 及以下的细字重。细字重在低分辨率工控屏和投影上会断笔；「细体大数字」是营销页面的风格，不是工程工具的风格。
3. **必须知晓系统中文字体的字重行为**：Windows 的微软雅黑实际只有 400 和 700 两档字形，浏览器会把 500 显示为 400、把 600 显示为 700。所以在 Windows 上，中文标签（500）看起来与正文同粗，中文标题（600）看起来是粗体。这可以接受：标签与正文之间仍靠字号和颜色区分，标题显示为粗体正是想要的效果；而 Inter 渲染的数字和英文能完整呈现 500、600 的细分。**不要**为了让中文标签显得更粗而改用 600，那会让所有标签变成粗体，彻底破坏层级。
4. 全局关闭浏览器的粗体合成（只关闭字重合成），避免缺少字重时浏览器用描边模拟粗体，把笔画糊成一片。

#### 2.2.4 行高规则

1. 所有行高都是 4px 的整数倍，保证文字落在 4px 基线网格上，具体值见 2.2.2。
2. 正文类（11 到 16px）行高约为字号的 1.33 到 1.5 倍；数据类（24px、32px）行高约为 1.1 到 1.15 倍。大号数字只有一行，紧凑的行高让数字和标签贴合成一个整体；正文需要宽松行高保证多行可读。
3. 多行段落（超过一行的报警原因、设置页说明文字）使用 `--lh-sm` 或 `--lh-md`，不得压到与字号相等。
4. 单行控件（按钮、输入框、导航项、表格行）用固定高度加垂直居中排版，不靠行高撑开高度。各控件高度见第四章。

#### 2.2.5 字距与数字排版

| 场景 | 字距 | 理由 |
|---|---|---|
| 中文文字（任何字号） | 0 | 方块字自带均匀间距，额外字距会让文字松散 |
| `--fs-3xl` 数字 | -0.64px（-0.02em） | Inter 大字号下默认字距偏松，收紧后读数更像一个整体 |
| `--fs-2xl` 数字 | -0.24px（-0.01em） | 同上，幅度减半 |
| 11px、12px 的纯英文大写（如 `CH1`、`ESP32`） | +0.24px（+0.02em） | 小号大写字母需要放松字距才不粘连 |
| 其余 | 0 | — |

数字排版规则：

1. 所有数值使用 `--font-data`（等宽数字）。表格数字列**右对齐**，让个位和小数点上下对齐。
2. **同一指标的小数位数固定，不随数值变化。** 应变指标保留 2 位；变化率保留 2 位并始终带符号（`+0.12`、`−0.05`、`±0.00`）；百分比保留 1 位。数值刷新时位数跳动会让整行左右抖动，等宽数字加固定位数可以彻底消除抖动。
3. 负号使用减号 `−`（U+2212），不用连字符 `-`。Inter 的减号与数字等宽、与加号对称；连字符偏短偏高，会破坏对齐。
4. ≥10000 的整数用半角逗号分隔千位（`12,480`），小数部分不分隔。
5. **无数据时显示 `--`**（两个半角连字符），颜色 `--text-tertiary`，字号和位置与有数据时完全相同。占位符必须与真实数据占同样的空间，避免数据到达时布局跳动。
6. 时间格式统一为 `YYYY-MM-DD HH:mm:ss`（24 小时制）。实时队列中当天的报警可以简写为 `HH:mm:ss`。「3 分钟前」这类相对时间只能出现在悬浮提示中作为补充，不得替代绝对时间。监测追溯需要精确时刻，相对时间在截图、导出、打印后会失去意义。

### 2.3 间距系统

#### 2.3.1 基础单位与阶梯

基础单位为 **4px**。所有外边距、内边距、间隙、元素尺寸都必须是 4 的整数倍。唯一例外是 1px 边框和 2px 焦点环。

| 变量 | 数值 | 典型用途 |
|---|---|---|
| `--sp-0` | 0 | 显式清零 |
| `--sp-1` | 4px | 状态点与等级文字之间；数值与单位之间；状态标签的垂直内边距 |
| `--sp-2` | 8px | 图标与按钮文字之间；行内元素之间；表格单元格垂直内边距；表单标签与输入框之间；按钮组内按钮之间 |
| `--sp-3` | 12px | 紧凑内边距；表格单元格水平内边距；面板标题与内容之间；小号按钮水平内边距 |
| `--sp-4` | 16px | **默认面板内边距**；面板之间的间隙；表单字段之间；默认按钮水平内边距 |
| `--sp-6` | 24px | 桌面页面边距；宽松内边距（对话框）；≥1920px 时的面板间隙 |
| `--sp-8` | 32px | 页面内大区块之间（如设置页两个分组之间）；登录表单内边距；≥1920px 时的页面边距 |
| `--sp-12` | 48px | 空状态的上下留白；登录页品牌区与表单之间 |

命名规则：序号乘以 4 等于像素值（`--sp-6` = 24px）。

阶梯中刻意**不提供** 20px、28px、40px。可选值越少，各页面间距越统一；面对「16 还是 20」时人容易犹豫，阶梯在 16 之后直接跳到 24，强制做出清晰的层级区分。旧方案的 `--sp-5: 20px` 废弃（迁移见第八章）。

#### 2.3.2 场景使用规则

| 场景 | 桌面（>768px） | 移动（≤768px） |
|---|---|---|
| 页面左右边距 | 24px；视口 ≥1920px 时 32px | 16px |
| 顶栏下沿到第一个面板 | 24px | 16px |
| 面板之间的间隙（水平与垂直） | 16px；视口 ≥1920px 时 24px | 12px |
| 面板内边距（默认） | 16px | 16px |
| 面板内边距（表格面板、图表面板） | 标题栏 12px 16px；内容区 0，由表格与图表自带内边距 | 同桌面 |
| 面板内边距（对话框） | 24px | 24px |
| 面板内边距（登录表单） | 32px | 24px |
| 面板标题与内容之间 | 12px | 12px |
| 表单字段之间（垂直） | 16px | 16px |
| 表单标签与输入框之间（标签在上） | 8px | 8px |
| 输入框与帮助文字、错误文字之间 | 4px | 4px |
| 表单分组之间 | 1px `--border-subtle` 分隔线，线上下各 32px | 线上下各 24px |
| 表单底部操作区与最后一个字段之间 | 24px | 24px |
| 按钮组内按钮之间 | 8px | 8px |
| 指标带单元格内边距 | 16px 24px | 12px 16px |
| 键值行（设备页、设置页） | 行高 36px；键列宽 128px；键与值间距 16px | 行高 44px |

理由：面板之间的间隙（16px）不大于面板内边距（16px），多个面板读作「一组」；页面边距（24px）大于面板间隙，形成清晰的内容外框。

规则：

1. **近者亲、远者疏**：同组元素的间距必须小于组与组之间的间距。间距是本系统建立分组的主要手段（原则三），间距错乱就是结构错乱。
2. 禁止用 margin 与 padding 叠加凑出阶梯外的数值（如 12px 加 6px 等于 18px）。
3. 禁止用负外边距对齐元素。需要视觉对齐时，调整容器内边距。

### 2.4 圆角系统

| 变量 | 数值 | 使用场景 |
|---|---|---|
| `--radius-none` | 0 | 表格（含表头）；指标带及其单元格；3D 画布区域；顶栏、侧栏；全宽通栏（如模拟模式提示条）；面板内部分区 |
| `--radius-xs` | 2px | 状态标签；复选框；进度条与阈值条的轨道和填充；HUD 测点标签 |
| `--radius-sm` | 4px | 按钮；输入框、下拉选择框；分段控件；HUD 视角按钮组；悬浮提示；导航项的悬停与激活底色块 |
| `--radius-md` | 6px | 面板与卡片；下拉菜单、用户菜单 |
| `--radius-lg` | 8px | 对话框；登录表单容器 |
| `--radius-full` | 9999px | 8px 状态点；开关的滑轨与滑块；头像；滚动条滑块 |

规则：

1. **圆角随元素尺寸和层级递增**：越小、越贴近数据的元素圆角越小；越大、越浮于表层的容器圆角越大。小元素上的大圆角会把它变成「胶囊」，丢失精密感；大容器用直角则显得生硬。按尺寸分级，圆角在视觉上才成比例。
2. **嵌套圆角**：内层元素紧贴外层边缘时，内层圆角等于外层圆角减去两者间距，结果小于 0 时取 0。例如 HUD 按钮组外框 4px、内部按钮贴边排列：首个与末个按钮的外侧角取 4px，内侧角取 0，中间按钮四角均为 0。
3. **贴合即直角**：元素与其他元素或屏幕边缘无缝拼接时，拼接处圆角为 0。
4. 禁止 12px 及以上的圆角。大圆角是消费级 App 和 AI 生成卡片的典型特征（第六章禁止）。
5. 禁止所有元素统一使用同一个圆角值。

### 2.5 阴影与层级系统

#### 2.5.1 阴影定义

| 变量 | 浅色 | 深色 | 使用场景 |
|---|---|---|---|
| `--shadow-none` | 无 | 无 | **所有常规面板与卡片。** 面板层次靠背景差与 1px 边框，不靠阴影 |
| `--shadow-sm` | `0 1px 2px rgba(22, 24, 29, 0.06)` | `0 1px 2px rgba(0, 0, 0, 0.40)` | 页面滚动距离大于 0 后的顶栏；3D 场景上的 HUD 按钮组与图例（帮助它们从模型上分离） |
| `--shadow-md` | `0 4px 12px rgba(22, 24, 29, 0.10)` | `0 4px 12px rgba(0, 0, 0, 0.50)` | 下拉菜单、用户菜单、日期选择弹层、悬浮提示 |
| `--shadow-lg` | `0 12px 32px rgba(22, 24, 29, 0.16)` | `0 16px 40px rgba(0, 0, 0, 0.60)` | 对话框；移动端抽屉；报警详情侧滑面板 |

规则：

1. **阴影只表达「浮在上方」这一物理层级，不表达重要性。** 重要的面板不加阴影，浮起的菜单才加阴影。
2. **阴影颜色只能是中性黑**，禁止彩色阴影与发光（如蓝色外发光、风险色光晕）。旧方案的 `--accent-glow`（发光）和 `--sheen`（内高光）全部废弃。
3. 深色主题的浮层（L2）必须同时具备三样东西：`--bg-raised` 背景、1px `--border-strong` 边框、对应阴影。缺一样，深色下的浮层就会与面板融为一体。
4. 悬停时不得给面板或卡片增加阴影，禁止「悬停浮起」效果。这是装饰性动效，还会让用户误以为整张卡片可以点击。

| `--z-sidebar` | 40 | 桌面侧栏 |
| `--z-dropdown` | 60 | 下拉菜单、用户菜单、底部固定的模拟场景条 |

### 2.6 动效系统

#### 2.6.1 时长

| 变量 | 数值 | 使用场景 |
|---|---|---|
| `--dur-instant` | 80ms | 按下态背景变化；复选框勾选 |
| `--dur-fast` | 150ms | 悬停态的背景、文字、边框颜色变化；悬浮提示出现；菜单收起 |
| `--dur-base` | 250ms | 下拉菜单展开；侧栏收起与展开（240px 与 64px 之间）；移动端抽屉滑入；对话框出现 |
| `--dur-slow` | 400ms | 风险等级切换时的颜色过渡；新报警行的高亮淡出 |

#### 2.6.2 缓动函数

| 变量 | 取值 | 使用场景 |
|---|---|---|
| `--ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | 默认：颜色过渡、尺寸变化、侧栏收起 |
| `--ease-enter` | `cubic-bezier(0, 0, 0.2, 1)` | 元素进入：菜单展开、抽屉滑入、对话框出现、悬浮提示出现 |
| `--ease-exit` | `cubic-bezier(0.4, 0, 1, 1)` | 元素离开：菜单收起、抽屉滑出、对话框关闭 |
| `--ease-linear` | `linear` | 加载条、骨架屏扫光、状态点脉冲 |

禁止带回弹的缓动（控制点 y 值大于 1 或小于 0 的贝塞尔曲线）以及弹簧动画。回弹是「活泼有趣」的情绪语言，与「冷静可信」的定位冲突；在监测场景里，一个数值或面板「弹一下」会让人误以为发生了什么。

#### 2.6.3 交互场景规范

| 场景 | 变化的属性 | 时长 | 缓动 | 说明 |
|---|---|---|---|---|
| 悬停 | 背景色、文字色、边框色 | `--dur-fast` | `--ease-standard` | **只改颜色，不改尺寸、位置、阴影** |
| 按下 | 背景色 | `--dur-instant` | `--ease-standard` | **禁止缩放。** 旧代码中按钮的 `transform` 过渡废弃，缩放会让周围布局产生视觉抖动 |
| 键盘焦点 | 焦点环 | 0，立即出现 | — | 延迟出现会让键盘用户迷失位置 |
| 下拉菜单展开 | 透明度 0 到 1，位移从向上 4px 到 0 | `--dur-base` | `--ease-enter` | 收起时只有透明度 1 到 0，`--dur-fast`，`--ease-exit` |
| 侧栏收起与展开 | 宽度 | `--dur-base` | `--ease-standard` | 收起开始时文字标签立即隐藏；展开结束后 80ms 文字淡入，避免文字在窄宽度下被挤压换行 |
| 移动端抽屉 | 水平位移 -100% 到 0；遮罩透明度 0 到 1 | `--dur-base` | 进入 `--ease-enter`；退出 `--ease-exit` | — |
| 对话框 | 透明度 0 到 1；缩放 0.98 到 1 | `--dur-base` | `--ease-enter` | 对话框是唯一允许缩放进入的元素，幅度仅 2% |
| 风险等级切换 | 风险指示器的背景、边框、文字颜色；风险单元格色条颜色 | `--dur-slow` | `--ease-standard` | 颜色交叉过渡，**不闪烁、不抖动** |
| 新报警入队 | 新行背景先保持对应级别的 `-bg` 1200ms，再用 `--dur-slow` 淡出到透明 | 1200ms 加 400ms | `--ease-linear` | 对应现有 `#alarmTable tr.row-new` 机制。未处理的报警和严重报警行本身就有常驻 `-bg` 底色，不淡出。只高亮一次，不重复闪烁 |
| 数据刷新：数值 | 无动画，直接替换 | 0 | — | 理由见下 |
| 数据刷新：图表 | 无动画，直接追加数据点 | 0 | — | 首次渲染允许 `--dur-base` 淡入，之后关闭动画 |
| 主题切换 | 无过渡，立即切换 | 0 | — | 全页元素同时过渡会产生「整页闪一下」的观感，且 3D 场景无法同步 |

数据刷新不做动画的理由：

- **数字滚动动画会显示从未真实出现过的中间值。** 对监测系统而言，屏幕上每一个数字都必须是真实测量值。哪怕只有 300ms 的虚假中间值，在截图取证时也会造成误导。
- 实时数据约每秒刷新一次。如果每次都做 300 到 400ms 的动画，画面将永远处于运动中，违背「界面安静」的核心理念。
- 等宽数字加固定小数位（2.2.5）已经保证刷新时布局不跳动，不需要动画去「平滑」。

#### 2.6.4 状态持续动效

全站只允许以下三种循环动画，其他任何无限循环动画一律禁止。

| 名称 | 作用对象 | 表现 | 周期 | 停止条件 |
|---|---|---|---|---|
| 严重报警脉冲 | 处置状态为「未处理」的严重报警：报警中心列表行的状态点；顶栏通知铃的计数点；3D 监测页风险单元格的状态点 | 8px 状态点透明度 1.0 → 0.35 → 1.0 | 1200ms，`--ease-linear` | 报警被处置为「已处理」，或风险等级降到严重报警以下 |
| 连接中 | 连接状态点，仅在「数据连接中」状态 | 8px 状态点透明度 1.0 → 0.35 → 1.0 | 1600ms，`--ease-linear` | 连接成功或判定离线 |
| 3D 测点涟漪 | 3D 场景中的测点 | 见第七章 | 随风险等级变化 | 离线时停止 |

规则：

1. 循环动画只能作用于 8px 状态点或 3D 测点，**禁止作用于整行、整块面板、整段文字或边框**。大面积闪烁造成视觉疲劳与焦虑，还可能诱发光敏性癫痫。WCAG 2.3.1 要求每秒闪烁不超过 3 次，本规范的 1200ms 周期远低于此上限。
2. **预警和报警不脉冲，只有未处理的严重报警脉冲。** 如果每个异常都在闪，就等于没有东西在闪。
3. 旧方案中的装饰性动效全部废弃：面板逐个入场的错峰延迟（`--d` 系列变量）、扫描光效、网格背景。功能性的 `.tk-track` 跑马灯如仍在使用则保留，滚动速度固定为 40px/s，`--ease-linear`。

#### 2.6.5 减弱动效

用户系统开启「减少动态效果」（`prefers-reduced-motion: reduce`）时：

1. 所有过渡时长降为 0，立即切换。
2. 循环脉冲停止，状态点保持完全不透明，改为在状态点外加一圈 1px 同色描边环（外径 12px）作为静态强调。
3. 3D 测点涟漪停止，测点保持静态；3D 视角切换改为瞬间跳转，不做相机飞行。
4. 新报警入队直接显示常驻底色，不做淡出。

理由：`static/app.css` 第 15 节已有减弱动效的降级路径。本规范在此基础上明确了每一项的替代表现，保证信息不因动效关闭而丢失：脉冲表达的「未处理」信息，由静态描边环继续表达。

### 3.1 全站骨架与栅格

#### 3.1.1 骨架结构

所有登录后页面共用 `_shell.html` 的骨架：左侧固定侧栏，右侧主区。主区自上而下是顶栏和内容区。

```
┌──────────┬──────────────────────────────────────────────┐
│          │ 顶栏 .sh-topbar            高 56px，sticky    │
│  侧栏    ├──────────────────────────────────────────────┤
│ .sh-side │                                              │
│          │ 内容区 .sh-content                            │
│ 展开 240 │   └ 内容容器 .sh-page                          │
│ 收起 64  │       └ 12 列栅格                              │
│          │                                              │
│ 高 100vh │                                              │
│ sticky   │                                              │
└──────────┴──────────────────────────────────────────────┘
```

3D 监测页是唯一例外：它不调用 `shell_topbar` 宏，而是用自己的 `.hero-top` 工具栏，下面接全幅 3D 画布（见 3.2）。

| 骨架尺寸变量 | 现值 | 新值 | 理由 |
|---|---|---|---|
| `--sh-side-w` | 240px | 240px（不变） | 能完整显示最长的导航标签「设备与数据源」（6 个汉字 84px）加图标和内边距，还留有余量 |
| `--sh-side-w-min` | 64px | 64px（不变） | 20px 图标加左右各 22px 留白 |
| `--sh-top-h` | 64px | **56px** | 顶栏只放一行标题加副标题（见 4.9），56px 足够；减少的 8px 留给内容区。3D 监测页 `.hero-top` 的 `--hero-top` 由 62px 同步改为 56px，保证两类页面的顶部高度一致 |

#### 3.1.2 内容区与容器

| 属性 | 桌面（>768px） | 移动（≤768px） |
|---|---|---|
| `.sh-content` 内边距 | 上 24px，左右 24px，下 32px；视口 ≥1920px 时左右 32px | 上 16px，左右 16px，下 24px |
| 安全区 | 左右内边距取「规定值」与 `env(safe-area-inset-left/right)` 两者中的较大值（沿用现有写法） | 同桌面 |
| `.sh-page` 最大宽度 | **1600px**，水平居中 | 无上限，占满 |

`.sh-page` 最大宽度由 1440px 调整为 1600px。理由：现场常用 1920px 宽显示器，侧栏展开后内容区约 1680px，1440px 上限会在两侧留下各 120px 的空白，显得内容「缩在中间」；1600px 可以基本铺满，同时在 2560px 宽屏上仍会居中，不会把一行文字拉到无法阅读的长度。

报警中心与设备与数据源当前通过 `max-width: none` 取消了上限（`alarms.html:48`），本规范统一回收：**这两个页面也使用 1600px 上限**，不再例外。理由：原则五要求七个页面共享同一套骨架；2560px 宽屏下把 7 列报警表格拉到 2300px 宽，每列之间空白过大，视线需要横跨很长距离才能把一行读完。

#### 3.1.3 12 列栅格

`.sh-page` 内部使用 12 列栅格。

| 视口宽度 | 列数 | 列间距（gutter） | 行间距 | 说明 |
|---|---|---|---|---|
| ≥1920px | 12 | 24px | 24px | 大屏 |
| 1280–1919px | 12 | 16px | 16px | 标准桌面，**设计基准** |
| 1024–1279px | 12 | 16px | 16px | 小桌面、笔记本；部分多列区域降列（见 3.4） |
| 769–1023px | 6 | 16px | 16px | 平板横屏、窄窗口。侧栏默认收起为 64px |
| ≤768px | 4 | 12px | 12px | 手机。侧栏变为抽屉 |

规则：

1. 面板宽度只能取整列，常用跨度：12（通栏）、8 + 4、6 + 6、4 + 4 + 4、3 + 3 + 3 + 3、9 + 3（主表格加侧栏）。
2. 列宽是流式的（等分剩余宽度），列间距固定。
3. 栅格只用于面板级布局。面板内部的元素排列（如指标卡内的数值与标签）不受 12 列约束，按组件规范的内部间距排列。
4. 禁止使用 `repeat(auto-fit, minmax(...))` 让浏览器自动决定列数（现有 `trend.html:17`、`alarms.html:60`、`device.html:78`、`history.html:36` 都在用）。理由：自动列数会在某些宽度下出现「3 张卡片一行 + 1 张卡片单独占一行」的孤儿布局，同一页面在 1366px 和 1440px 下排布完全不同。改为在 3.4 的断点表中明确规定每个区域在每个断点的列跨度。

#### 3.1.4 废除视口缩放系数

`alarms.html` 与 `device.html` 中的 `--pg-s` 缩放系数（在 1440px 到 2592px 之间把字号、间距、图表尺寸线性放大到 1.25 倍），以及 `alarms.html` 中基于它的 JS 计算，**全部废除**。所有页面在任何视口宽度下使用第二章规定的固定字号与间距。

理由：

- 它让同一个组件在不同页面字号不同（报警中心 1920px 下指标数字为 37.5px，实时趋势页同一类数字为 30px），违反原则五。
- 宽屏多出来的空间应该用来显示更多信息（更多列、更长的时间窗、更多表格行），而不是把同样的信息放大。这是工程工具与展示大屏的根本区别：Grafana 和 Linear 在宽屏上都不放大字号。
- 它与 D4「全站流式布局、废弃缩放方案」的决策同源：缩放的问题不在于用的是 `transform` 还是 `calc`，而在于「按视口放大」这件事本身。

宽屏利用空间的方式，由 3.4 断点表中的「≥1920px」一列规定。

#### 3.1.5 高度策略

| 页面 | 高度策略 | 理由 |
|---|---|---|
| 3D 监测 | 画布精确铺满：高度 = 视口高 − `.hero-top` 56px − 模拟条高度（模拟模式 48px，否则 0）。页面本身不滚动 | 3D 场景是一个「窗口」，出现滚动条会破坏沉浸感，并与 3D 场景的滚轮缩放冲突 |
| 报警中心、设备与数据源 | 内容区最小高度 = 视口高 − 顶栏 56px − 内容区上下内边距 56px。主表格面板吃掉剩余高度，表格内部滚动 | 值班人员在报警中心停留时间最长，处置队列需要最大化显示行数，且表头必须始终可见 |
| 实时趋势、历史与导出、系统设置 | 自然高度，页面整体滚动 | 内容是若干个固定高度的面板，没有必要强行铺满 |

铺满高度的计算由 CSS 完成（视口高度单位加上述固定值），不得用 JS 定时测量。现有 `alarms.html:683` 每 1000ms 执行一次 `layoutFill()` 测量布局，随 `--pg-s` 一同废除。理由：每秒强制一次布局计算是持续的性能开销，并且布局会在数据刷新时出现肉眼可见的跳动。

理由：5 个各带圆角、阴影、毛玻璃的小卡片（现有 `dashboard.html:114`）正是第六章禁止的「圆角卡片堆叠」；改为一条通栏后，5 个指标读作一组仪表读数，左边缘对齐，视觉上更安静，也更接近工业 HMI 的状态栏形态。

#### 3.2.3 全屏观看模式

模拟模式下，全屏时模拟条虽然隐藏，**左上角必须保留一个「模拟」标签**（距左上各 16px，见 4.12 模拟标识）。理由：原则二，模拟模式在任何视图下都不得被隐藏，否则全屏截图会被误当作真实监测数据。

### 3.3 导航结构

#### 3.3.1 结构

保留现有的**左侧侧栏导航**，不改为顶部导航。

理由：

- 六个导航项加用户区，纵向排列比横向排列更易扫读，也为将来增加页面留有余地。
- 顶部导航会占用垂直空间。3D 监测页、报警中心都需要最大化垂直高度，而现场显示器多为 16:9，水平空间比垂直空间富余。
- 侧栏可收起到 64px，在需要专注 3D 场景时几乎不占空间。

侧栏自上而下：

| 区块 | 高度 | 内容 |
|---|---|---|
| 品牌区 `.sh-side-head` | 56px（与顶栏同高，两者下边线对齐成一条水平线） | 产品标志 + 「桥体卫士」 + 收起按钮 |
| 导航区 `.sh-nav` | 弹性 | 6 个导航项，按现有顺序：3D 监测、实时趋势、报警中心、历史与导出、设备与数据源、系统设置 |
| 底部区 `.sh-side-foot` | 按内容 | 用户行（头像 + 用户名 + 「已登录」）+ 主题切换 + 退出登录 |

品牌区下边线与顶栏下边线必须在同一水平线上（都是 56px 处的 1px `--border-default`）。理由：这是一个跨区域的对齐细节，两条线对齐后，侧栏与主区形成一个连续的「标题栏」带，骨架显得严谨；不对齐会产生 8px 的错位台阶，是最常见的「不精致」来源。

主题切换控件（D1 新增）放在侧栏底部区，与退出登录并列，图标按钮，收起状态下同样可见。不放在顶栏的理由：主题切换是低频的个人偏好设置，不应与连接状态、通知这类实时信息争夺顶栏的注意力。

#### 3.3.2 导航项状态

导航项具体尺寸、颜色、状态见第四章 4.9，这里只规定状态逻辑：

| 状态 | 视觉 | 理由 |
|---|---|---|
| 默认 | 图标与文字 `--text-secondary`，无背景 | — |
| 悬停 | 背景 `--bg-hover`，图标与文字 `--text-primary` | 只改颜色（2.6.3） |
| 激活（当前页） | 背景 `--bg-selected`，文字 `--text-primary` 加 `--fw-semibold`，图标 `--accent-default`；左侧 2px 宽、16px 高的 `--accent-default` 竖条，竖条贴侧栏内边缘，垂直居中 | 背景、字重、图标颜色、指示条四重冗余，在投影仪等低对比度环境下也能看清当前位置 |
| 激活 + 悬停 | 保持激活态，不叠加悬停色 | 避免激活项在鼠标经过时「闪」一下 |
| 键盘焦点 | 2px 焦点环（2.1.3），与其他状态可叠加 | — |
| 报警中心有未处理的严重报警 | 导航项文字右侧显示计数徽标（见 4.9） | 让用户在任何页面都能感知未处理的严重报警 |

#### 3.3.3 收起态

桌面侧栏收起为 64px 时：

- 只显示图标，图标在 64px 宽内水平居中。
- 激活项的 `--bg-selected` 背景缩为 40 × 40px 的方块，居中；左侧竖条保留。
- 悬停导航项时，在其右侧 8px 处显示提示气泡，内容为导航标签文字（现有 `data-tip` 机制），样式见 4.12 悬浮提示。
- 报警计数徽标缩为 8px 红点，位于图标右上角，向外偏移 2px。
- 收起状态存储在 `localStorage['bg.sidebar.collapsed']`（现有机制不变）。视口高度 ≤860px 时默认收起（现有机制不变）。

#### 3.3.4 顶栏

顶栏左侧为页面标题和副标题，右侧为全局状态区。从右往左依次是：

| 顺序（从右起） | 元素 | 说明 |
|---|---|---|
| 1 | 用户菜单按钮 `.sh-user-btn` | 头像 + 下拉箭头 |
| 2 | 通知铃 `.sh-bell` | 跳转报警中心；有未处理报警时显示计数 |
| 3 | 连接状态 `.conn` | 状态点 + 文字（「数据连接正常」「连接中」「离线」） |
| 4 | 模拟标识 `.sh-sim-badge` | 仅模拟模式显示 |

右侧元素之间间距 8px；连接状态与通知铃之间额外加一条 1px × 20px 的 `--border-default` 竖向分隔线，分隔线左右各 8px。理由：左边两项（模拟标识、连接状态）是**数据状态**，右边两项（通知、用户）是**操作入口**，用分隔线把两类信息分开。

右侧状态区的顺序固定。最靠近页面标题的是模拟标识，因为它会改变对整页数据的理解，必须最先被看到。

## 四、组件规范

本章每个组件都按同一结构描述：**挂载类名**（现有类名，D6 不改名）、**结构**、**尺寸**、**颜色**、**状态**、**动效**、**理由**。新组件或新增子元素使用 BEM 命名，前缀 `bg-`（Bridge Guardian），见第八章。

通用约定：

- 下文的「状态点」均指 8 × 8px、`--radius-full` 的实心圆，颜色取对应状态的 `-main`。状态点与紧随其后的文字间距 `--sp-1`（4px），垂直居中对齐文字的 x 高度中线。
- 下文出现的「数值」一律使用 `--font-data`、`--text-primary`，遵守 2.2.5 的数字排版规则。
- 下文的高度是元素的外框高度（含边框）。

### 4.1 指标卡片

系统里有两种形态的指标卡：**通栏单元格**（3D 监测页画布顶部的指标带）和**独立卡片**（实时趋势、报警中心、设备与数据源三个页面顶部的指标卡行，以及历史页的统计指标）。两者共享同一套内部结构，只有容器不同。

#### 4.1.1 内部结构（两种形态共用）

自上而下三行，全部左对齐：

| 行 | 内容 | 字号 / 字重 / 颜色 | 行高 |
|---|---|---|---|
| 1. 标签行 | 指标名称（如「当前应变指标」）；右侧可选趋势指示 | `--fs-xs` / `--fw-medium` / `--text-tertiary` | 16px |
| 2. 数值行 | 数值 + 单位 | 主读数 `--fs-3xl` / `--fw-bold`；次要数值 `--fs-2xl` / `--fw-semibold`；单位按 2.2.2 规则 3 | 36px 或 28px |
| 3. 说明行（可选） | 补充说明（如「超过 1.0 / 1.1 / 1.2 倍依次预警、报警、严重报警」） | `--fs-xs` / `--fw-regular` / `--text-tertiary`；单行，超出省略 | 16px |

行间距：标签行与数值行之间 `--sp-1`（4px）；数值行与说明行之间 `--sp-1`（4px）。

**单位显示**：后端单位口径为「相对应变指标」（无量纲，`datasource.py:31` 的 `UNIT`），它是一个说明性名称而不是物理单位符号。因此：数值后面**不跟**这六个字（现有 `#strainUnit` 等元素在视觉上隐藏，保留元素与 ID）；单位口径统一在页脚说明一次（现有「单位口径：……（无量纲，非工程微应变）」）。有真实单位的数值照常跟单位：采集周期跟「秒」，累计采样跟「次」，按 2.2.2 规则 3 的字号与颜色。理由：在 32px 主读数后面跟 14px 的「相对应变指标」六个字，会比数字本身还宽，而它对读数没有任何换算意义。

**标签行不放图标。** 现有 `trend.html:94` 等处在标签前放了一个 16px 的线性图标（`.pg-glyph`），本次删除。理由：四张卡片各配一个装饰性图标，并不帮助用户区分它们（标签文字已经足够），属于第六章所说的「装饰性元素」；删掉后标签与数值的左边缘对齐更干净。

**趋势指示**（可选，只用于有时间序列的数值，如「当前应变指标」「变化率」）：

- 位置：标签行右端，与标签文字基线对齐。
- 内容：方向符号 + 变化量，如 `▲ 0.12`、`▼ 0.05`、`— 0.00`。方向符号使用 U+25B2 / U+25BC / U+2014，`--fs-2xs`；变化量 `--fs-xs`，`--font-data`。
- 颜色：**一律 `--text-tertiary`，不使用红绿。**

  理由：在桥梁应变监测中，「上升」不一定是坏事（比如车辆刚通过后的正常回弹），「下降」也不一定是好事。股票软件式的红涨绿跌会把方向错误地编码成好坏，违反原则一。数值是否危险，只由风险等级判断。

- 无数据或离线时整个趋势指示隐藏，不显示 `—`（避免与「无变化」混淆）。

**状态色条**（只用于风险相关的指标，即「风险等级」单元格与报警中心的「待处置报警」卡片）：

- 位置：卡片或单元格的**左边缘**，贴边，垂直方向占满。
- 宽度：正常 0（不显示）、预警 2px、报警 3px、严重报警 4px，与 2.1.4 规则 1 一致。
- 颜色：对应等级的 `-main`。
- 未知状态：宽 4px，`--trust-unknown-stripe` 与透明交替的 45° 斜线纹理。
- 色条占据的宽度从内容区的左内边距中扣除，保证内容的左边缘位置不因等级变化而移动。

  理由：色条放左侧而不是顶部，是因为人的视线从左向右扫描，左边缘的颜色会最先被看到；也和报警队列项的左侧色条（4.3）形成全站一致的「左边缘即等级」的阅读习惯。

#### 4.1.2 形态 A：通栏单元格（3D 监测页 `.metric-strip`）

挂载类名：`.metric-strip`（容器）、`.ms-item`（单元格）、`.ms-k`（标签）、`.ms-v`（数值）、`.ms-item.ms-risk`（风险等级单元格），保留全部现有 ID。

| 属性 | 规范 |

**删除的内容**：现有每个 `.ms-item` 上的独立圆角（10px）、独立阴影、`backdrop-filter: blur(6px)`（`dashboard.html:116`），以及严重报警时整个单元格的 `msPulse` 脉冲动画（`dashboard.html:138`）。脉冲改为只作用于风险等级指示器内的状态点（2.6.4 规则 1）。

tablet 档（769–1023px）：容器高度 152px，分两行。第一行风险等级与当前应变指标（各占 50%）；第二行其余三项（各占 33.33%）。两行之间 1px `--border-subtle` 横线，左右各缩进 16px。

挂载类名：`.card.stat-card`，以及各页面自己的变体 `.pg-stat`（实时趋势）、`.pa-stat`（报警中心）、`.dv-stat`（设备与数据源）、`.stat`（历史与导出）。这些变体类名保留，但**视觉规则全部统一到 `.stat-card` 上**，页面变体类不再承载任何颜色、字号、间距。

### 4.2 风险等级指示器

风险等级指示器是全站唯一一个**文字本身使用风险色**的组件（2.1.5 规则 2 的例外）。它有三种尺寸形态，挂在不同位置。

#### 4.2.1 结构

`[状态点] [等级文字]`，横向排列，状态点在左。不使用 emoji、不使用字符模拟状态点。现有 `dashboard.html:612` 的 `SEV` 表为每个等级配了一个字符图标（正常 `●`、预警 `▲`、报警 `■`、严重报警 `◆`、离线 `U+26D4`（禁止通行符号）），由 `dashboard.html:730` 写入 `#msRiskIcon`。其中 `U+26D4`（禁止通行符号） 是 emoji，直接违反第六章；其余几何字符的大小、位置随字体变化，在微软雅黑与 Inter 下大小相差约 30%，且无法精确控制与文字的垂直对齐。处理方式：`#msRiskIcon` 元素与 ID 保留，JS 写入字符的逻辑可以不改，但该元素的字符内容在视觉上隐藏，改由 CSS 按 `data-risk` 绘制状态点（实心圆或空心虚线圆）。色弱冗余编码由 2.1.4 规则 1 的「色条宽度 + 标签形态」承担，不再依赖字符形状。

#### 4.2.2 尺寸形态

| 形态 | 使用位置 | 状态点 | 文字 | 容器 |
|---|---|---|---|---|
| 大号 | 3D 监测页指标带「风险等级」单元格（`#msRisk`、`#riskLabel`） | 12 × 12px | `--fs-3xl` / `--fw-semibold` | 无容器，直接置于单元格数值行 |
| 中号 | 实时趋势页指标卡（如显示风险等级）；设备页连接状态主读数 | 8 × 8px | `--fs-lg` / `--fw-semibold` | 无容器 |
| 小号（徽标） | 表格「等级」列、报警详情、报警中心统计图例 | 无状态点（徽标本身的颜色已足够），**正常态例外**：正常态没有底色，必须加 8px 状态点 | `--fs-xs` / `--fw-medium` | 见 4.2.3 |

大号形态的状态点 12px 而不是 8px：32px 文字旁的 8px 圆点视觉上过小，比例失调。12px 是全站唯一一个非 8px 的状态点。

#### 4.2.3 五态视觉表达

| `data-risk` | 大号 / 中号：状态点 | 大号 / 中号：文字颜色 | 文字内容 | 小号徽标 |
|---|---|---|---|---|
| `normal` | `--risk-normal-main` | `--risk-normal-text` | 正常 | 无底色、无边框；8px 状态点 + `--risk-normal-text` 文字 |
| `warn` | `--risk-warn-main` | `--risk-warn-text` | 预警 | 高 20px，左右内边距 8px，`--risk-warn-bg` 底，1px `--risk-warn-border` 边框，`--risk-warn-text` 文字，`--radius-xs` |
| `alarm` | `--risk-alarm-main` | `--risk-alarm-text` | 报警 | 同上，换成 alarm 系列 |
| `crit` | `--risk-crit-main`；未处理时脉冲（2.6.4） | `--risk-crit-text` | 严重报警 | 高 20px，左右内边距 8px，**实心**：`--risk-crit-main` 底，`--risk-crit-solid-text` 文字，无边框，`--radius-xs` |
| `offline` | 不显示实心状态点，改为 12px（大号）/ 8px（中号）的**空心**圆：1px `--trust-unknown-main` 虚线描边 | `--trust-unknown-text` | **未知** | 高 20px，左右内边距 8px，`--trust-unknown-bg` 底，1px **虚线** `--trust-unknown-border` 边框，`--trust-unknown-text` 文字「离线」 |

注意离线态在大号、中号上显示「未知」，在小号徽标上显示「离线」。理由：大号、中号回答的问题是「风险等级是多少」，答案是「未知」；小号徽标出现在报警记录里，回答的是「这条记录是什么事件」，答案是「离线」（即设备离线规则产生的事件）。这一区分直接来自 D7 与 `CONTEXT.md` 中「离线」与「风险等级」的定义。

#### 4.2.4 动效

等级切换时，状态点颜色、文字颜色、徽标底色与边框按 `--dur-slow` / `--ease-standard` 交叉过渡；文字内容直接替换。不做闪烁、缩放、抖动。

现有 `.risk-card` 的 `pulse` / `heroPulse` 动画（`app.css:1902` 附近注释所列）删除。

### 4.3 报警队列项

报警队列在报警中心以表格呈现（`.data-table`，7 列：时间、应变指标、等级、规则、原因、状态、操作），移动端转为卡片列表。本节规定**单条报警**的信息层级与视觉；表格本身的通用规范见 4.11。

#### 4.3.1 信息层级

一条报警回答四个问题，按重要性排序：

| 优先级 | 问题 | 字段 | 视觉权重 |
|---|---|---|---|
| 1 | 有多严重？ | 等级 | 左侧色条 + 等级徽标（最先被看到） |
| 2 | 什么规则触发的？ | 规则名 | `--fs-md` / `--fw-semibold` / `--text-primary` |
| 3 | 为什么？触发值是多少？ | 原因 + 应变指标 | 原因 `--fs-sm` / `--fw-regular` / `--text-secondary`；应变指标数值 `--fs-sm` / `--font-data` / `--text-primary` |
| 4 | 什么时候？处理了吗？ | 时间 + 处置状态 | 时间 `--fs-xs` / `--font-data` / `--text-tertiary`；处置状态见下 |

规则名是 6 个固定值之一：阈值超限、变化率突变、持续超限、短时波动、基线偏移、设备离线（或设备恢复）。规则名不加引号、不加图标。

#### 4.3.2 桌面表格行（报警中心）

列顺序保持现有顺序不变（时间、应变指标、等级、规则、原因、状态、操作），列宽与对齐如下：

| 列 | 宽度 | 对齐 | 内容样式 |
|---|---|---|---|
| 时间 | 160px 固定 | 左 | `--fs-sm` / `--font-data` / `--text-tertiary`（与 4.3.1 一致，时间是优先级最低的信息）；格式 `YYYY-MM-DD HH:mm:ss` |
| 应变指标 | 96px 固定 | **右** | `--fs-sm` / `--font-data` / `--text-primary`；设备事件行显示 `--`（现有逻辑） |
| 等级 | 96px 固定 | 左 | 小号风险徽标（4.2.2） |
| 规则 | 112px 固定 | 左 | `--fs-sm` / `--fw-semibold` / `--text-primary` |
| 原因 | 弹性，吃掉剩余宽度，最小 240px | 左 | `--fs-sm` / `--text-secondary`；单行，超出省略，悬停显示完整原因的悬浮提示 |
| 状态 | 80px 固定 | 左 | 「未处理」：`--fs-sm` / `--fw-medium` / `--text-primary`，前置 8px 空心圆（1px `--text-tertiary` 描边）；「已处理」：`--fs-sm` / `--text-tertiary`，前置 8px 实心圆 `--risk-normal-main` |
| 操作 | 88px 固定 | 右 | 未处理时显示「确认处理」按钮（`.ack-btn`，小号次要按钮，见 4.8）；已处理时为空 |

表格中规则名在桌面使用 `--fs-sm`（13px），比 4.3.1 中的 `--fs-md` 小一档：表格行内所有文字统一 13px，层级靠字重与颜色区分，避免同一行文字大小参差。

行级规范：

| 属性 | 规范 |
|---|---|
| 行高 | 44px |
| 单元格内边距 | 垂直 12px，水平 12px；首列左内边距 16px，末列右内边距 16px |
| 左侧色条 | 首个单元格的左边缘，按等级宽度（预警 2 / 报警 3 / 严重报警 4px），`-main` 色；正常级无色条（报警记录里不会出现正常级）；设备离线事件为 4px 斜线纹理 |
| 未处理行背景 | 报警与严重报警：对应 `-bg`；预警：无底色（只有色条）；设备离线：`--trust-unknown-bg` |
| 已处理行背景 | 透明；色条保留但透明度降为 40%；所有文字降一级（primary → secondary，secondary → tertiary） |
| 行分隔 | 1px `--border-subtle` |
| 悬停 | 背景 `--bg-hover`（叠加在未处理底色之上时，改为将底色加深：浅色主题叠加 4% 黑，深色主题叠加 4% 白） |
| 选中（点击行打开详情） | 背景 `--bg-selected`；色条保留 |
| 新入队 | `.row-new`：按 2.6.3「新报警入队」规则 |

已处理行降级的理由：处置闭环的目的是把注意力集中到未处理的报警上。已处理的记录仍需可追溯，但不应与未处理的记录争夺注意力。

预警未处理时不铺底色的理由：预警数量通常最多，如果每条都铺琥珀底色，表格会变成一片黄色，真正需要注意的报警与严重报警反而不突出。

#### 4.3.3 报警详情面板（`.alarm-detail`）

点击表格行后在表格下方展开（现有机制）。

| 属性 | 规范 |
|---|---|
| 容器 | `--bg-subtle` 背景，上边框 1px `--border-default`，内边距 16px，圆角 0（贴合在表格面板底部） |
| 标题行 `.d-title` | 等级徽标 + 规则名（`--fs-md` / `--fw-semibold` / `--text-primary`，**不再使用强调色**）+ 右侧时间（`--fs-xs` / `--text-tertiary`） |
| 原因 `.d-reason` | `--fs-sm` / `--lh-sm` / `--text-primary`；完整显示，不截断；原因中的数字部分保持 `--font-data` |
| 键值信息 | 触发值、阈值、处置状态，使用 4.7 中的键值行样式，横向排列，每项之间 24px |
| 操作 | 右下角：未处理时显示主按钮「确认处理」（这是此时该视口唯一的主按钮） |
| 展开动效 | 高度从 0 展开 + 透明度 0→1，`--dur-base` / `--ease-enter`。替换现有 `detailIn` |

#### 4.3.4 移动端卡片

### 4.4 ECharts 仪表盘

挂载：`#gauge`（实时趋势页「阈值仪表盘」面板）。现有配置在 `trend.html:404` 附近。

#### 4.4.1 读取 token 的方式

ECharts 不能直接使用 CSS 变量。实现要求：

1. 写一个统一的取色函数，在初始化图表和**每次主题切换后**，从根元素的计算样式中读取本章用到的变量值。
2. 所有 ECharts 配置中的颜色、字号、字体都从这个函数取得，**禁止**在 JS 中写色值字面量（现有 `trend.html` 中的 `'#16a34a'`、`'#be123c'`、`'#cbd5e1'`、`rgba(22, 163, 74, .28)` 等全部替换）。
3. 主题切换时，对每个图表实例重新调用设置配置的方法（完整替换，不合并），而不是销毁重建，以保留数据与缩放状态。

#### 4.4.2 几何

| 属性 | 现值 | 新值 | 理由 |
|---|---|---|---|
| 起止角度 | 205° → −25°（230° 弧） | **210° → −30°（240° 弧）** | 240° 是工业压力表、应变仪表的标准弧度，开口朝下对称 |
| 半径 | 76% | 80% | 移除装饰后有空间放大表盘 |
| 圆心 | (50%, 58%) | (50%, 55%) | 让开口区域留给数值读数 |
| 量程 | 0 到 阈值 × 5/3 | 不变 | 现有口径，面板副标题已说明 |
| 主刻度数 | 5 | 5（即 6 个刻度标签） | — |

#### 4.4.3 表盘与色带

| 元素 | 规范 |
|---|---|
| 轨道（axisLine） | 宽 **8px**（现值 14px）。分段着色：0 到阈值为 `--bg-sunken`（中性轨道，不着绿色）；阈值到 1.1 倍阈值为 `--risk-warn-main`；1.1 到 1.2 倍为 `--risk-alarm-main`；1.2 倍以上为 `--risk-crit-main`。端头平头，不做圆头 |
| 进度条（progress） | **不使用**。理由：轨道色带本身已经标示了危险区间，指针已经指示了当前位置，再叠加一条进度弧是冗余墨水 |
| 主刻度（splitLine） | 长 12px，宽 1px，`--text-tertiary`，位于轨道内侧，与轨道内沿相距 4px |
| 次刻度（axisTick） | 每个主刻度间 5 个，长 6px，宽 1px，`--border-strong`，同样位于轨道内侧 |
| 阈值刻度 | 在阈值位置额外画一条长 16px、宽 2px 的 `--chart-threshold` 刻度，穿过轨道，标示「这里开始报警」 |
| 刻度标签（axisLabel） | `--fs-2xs` / `--font-data` / `--chart-label`；距轨道 24px（在次刻度内侧） |

色带分段的理由：预警、报警、严重报警的分界点（1.0 / 1.1 / 1.2 倍阈值）是后端判定的真实口径（`trend.html:113` 的说明行已写明），仪表的色带必须与之完全一致，否则用户会看到「指针在橙色区但判定只是预警」的矛盾。正常区间用中性灰而不是绿色，遵守原则一：正常就是安静。

#### 4.4.4 指针与读数

| 元素 | 规范 |
|---|---|
| 指针 | 细长三角形，长度为半径的 70%，根部宽 4px；颜色 `--text-primary`（**不随风险等级变色**）；**删除现有的阴影光晕**（`shadowBlur: 8`） |
| 指针轴心（anchor） | 直径 10px 圆，`--bg-surface` 填充，2px `--text-primary` 描边 |
| 读数（detail） | 位于圆心下方，偏移半径的 40%；`--fs-3xl` / `--fw-bold` / `--font-data` / `--text-primary`；**不随风险等级变色**（现有配置随等级变色）；无数据时 `--` / `--text-tertiary` |
| 单位与标题（title） | 读数下方 4px；`--fs-xs` / `--text-tertiary`，内容为单位 |
| 指针动画 | 首次渲染 `--dur-base`；后续数据更新**关闭动画**，指针直接跳到新位置（2.6.3） |

指针与读数不随风险变色的理由与 2.1.5 规则 2 相同：数值本身必须始终以最高可读性显示；危险程度已经由指针落在哪个色带区间表达。

#### 4.4.5 仪表下方的读数行（`.pg-gaugefoot`）

保留现有结构「当前指标 / 报警阈值」两项，横向排列，两端对齐。标签 `--fs-xs` / `--text-tertiary`，数值 `--fs-sm` / `--fw-semibold` / `--font-data` / `--text-primary`，标签与数值间距 8px。上方 1px `--border-subtle` 分隔线，分隔线与仪表、与读数行各间距 12px。

### 4.5 ECharts 折线图

挂载：`#chart`（实时趋势主图）、`#miniChart`（近段采样）、`#histChart`（历史数据比对）。三个图表共用以下规范，差异在 4.5.6 列出。

#### 4.5.1 网格（grid）

| 属性 | 规范 |
|---|---|
| 绘图区内边距 | 上 16px，右 16px，下 32px（容纳 X 轴标签），左按 Y 轴标签宽度自动计算（`containLabel`），最小 40px |
| 背景 | 透明（继承面板 `--bg-surface`） |
| 边框 | 无 |

#### 4.5.2 坐标轴

| 元素 | X 轴（时间） | Y 轴（应变指标） |
|---|---|---|
| 轴线 | 1px `--chart-axis` | **不显示** |
| 刻度线 | 不显示 | 不显示 |
| 刻度标签 | `--fs-2xs` / `--font-data` / `--chart-label`；距轴线 8px；格式 `HH:mm:ss`（跨天时首个标签与跨天处显示 `MM-DD HH:mm`）；标签自动间隔，相邻标签最小间距 64px，不旋转 | `--fs-2xs` / `--font-data` / `--chart-label`；右对齐，距绘图区 8px；分段数 4 到 5 段；小数位与该指标固定位数一致 |
| 网格线 | **不显示**（2.1.6） | 1px 实线 `--chart-grid` |
| 轴名称 | 不显示 | 不显示；单位口径写在页脚（现有「单位口径：相对应变指标（无量纲，非工程微应变）」），图表内不重复 |

Y 轴起点：使用数据自适应范围（现有 `scale: true`），但**阈值线必须始终在可视范围内**：Y 轴上限取「数据最大值」与「阈值 × 1.25」中的较大者。理由：如果数据远低于阈值时阈值线被裁出画面，用户就失去了「离危险还有多远」的参照，这正是监测图表最重要的信息。

#### 4.5.3 数据线

| 属性 | 规范 | 现状 |
|---|---|---|
| 主数据线颜色 | `--chart-series-primary`（墨色） | 现为强调绿 `#16a34a` |
| 线宽 | 主图 1.5px；近段采样 1.5px；历史图 1.5px | 现为 2px 和 1.6px |
| 平滑 | **关闭**（折线） | 现为 `smooth: true` |
| 数据点标记 | 不显示；悬停时在当前点显示 6px 实心圆（`--chart-series-primary` 填充，2px `--bg-surface` 描边） | 现为不显示 |
| 降采样 | 保留 `lttb` | — |
| 面积填充 | 单曲线时使用 `--chart-area` **纯色**填充；多曲线时不填充 | 现为绿色渐变面积 |

关闭平滑的理由：平滑曲线会在采样点之间插值出**从未测到的数值**，尤其在数据突变（变化率突变规则所监测的正是这种情况）处会产生虚假的过冲与回弹，把真实的阶跃变成波浪。工程测量数据必须如实呈现每个采样点之间的线性关系。这与 2.6.3 不做数字滚动动画是同一原则。

纯色而不是渐变填充的理由：第六章禁止渐变；纯色 6% 透明度的面积足以帮助眼睛把曲线读作「一块面积」，从而更容易感知整体水位。

#### 4.5.4 超限区段着色

曲线超过阈值的部分，按所处区间分段着色（ECharts 的分段视觉映射，按 Y 值分段）：

| Y 值区间 | 线色 |
|---|---|
| ≤ 阈值 | `--chart-series-primary` |
| 阈值 到 1.1 × 阈值 | `--risk-warn-main` |
| 1.1 到 1.2 × 阈值 | `--risk-alarm-main` |
| > 1.2 × 阈值 | `--risk-crit-main` |

面积填充不参与分段着色，始终为 `--chart-area`。

理由：这是图表中唯一使用颜色的地方，并且严格表达语义：「这一段超限了，超到了哪一级」。分界点与仪表盘色带、后端判定口径完全一致。

#### 4.5.5 参考线与交互

| 元素 | 规范 |
|---|---|
| 阈值线（markLine） | 1px，6px 实 + 4px 空虚线，`--chart-threshold`；**不显示端点符号**；右端标签「阈值 {值}」，`--fs-2xs` / `--font-data` / `--risk-alarm-text`，位于线的上方 4px、绘图区右内侧 |
| 预警 / 严重报警分界线 | 不画。理由：三条参考线会让图表过于拥挤；超限区段的着色已经表达了分级 |

### 4.6 3D 场景 HUD 覆盖层

挂载：`.twin-hud`（HUD 层）、`.twin-hud-view`（视角工具条）、`.th-presets`（视角按钮组）、`.th-zooms`（缩放组）、`.th-toggles`（开关组）、`.th-btn`（按钮）、`.th-btn.on`（激活）、`.th-mode-tag`（操作提示）、`.twin-hud-detail`（测点详情）、`.twin-hud-hint`（鼠标提示）、`.twin-labels`（测点标签层）、`.scene-label`（跨中测点标签）、`.twin-status`（加载与错误状态）。这些类名由 `static/js/twin/hud.js` 生成，**全部保留**。

HUD 设计的总原则：**HUD 元素是贴在镜头上的仪表，不是场景里的物体。** 它们使用与页面其他部分完全相同的组件语言（同样的按钮、同样的字体、同样的 token），只是底板换成 `--hud-bg`。不使用任何专属于 3D 的「科幻」视觉（角标装饰、扫描线、六边形、发光描边）。

#### 4.6.1 视角工具条（`.twin-hud-view`）

位置：画布左下角，距左、下各 16px。

结构：从左到右三组，组与组之间 8px 间距，每组是一个独立的分段控件：

| 组 | 内容 | 类型 |
|---|---|---|
| 视角组 `.th-presets` | 全桥、主跨、桥塔、峡谷、桥面（5 个，现有 `viewPresets`） | 单选分段控件，始终有一项激活 |
| 缩放组 `.th-zooms` | 放大、缩小 | 普通按钮组 |
| 开关组 `.th-toggles` | 自动旋转、结构线框、测点标注（三态循环：测点标注 / 仅跨中 / 标注关闭）、复位视角 | 开关按钮组；复位视角为普通按钮 |

分段控件规范：

| 属性 | 规范 |
|---|---|
| 组外框 | 1px `--hud-border`，`--radius-sm`，`--hud-bg` 底，`--shadow-sm` |
| 按钮高度 | 32px |
| 按钮内边距 | 水平 12px |
| 按钮间分隔 | 1px `--border-subtle` 竖线，上下贴满 |
| 按钮圆角 | 按 2.4 规则 2：首个按钮左侧两角 4px，末个按钮右侧两角 4px，其余为 0 |
| 文字 | `--fs-sm` / `--fw-medium` / `--hud-text-muted` |
| 悬停 | 背景 `--bg-hover`，文字 `--hud-text` |
| 激活 `.on`（视角组当前视角、开关组开启项） | 背景 `--bg-selected`，文字 `--accent-default`，`--fw-semibold`。**不使用实心强调色填充**（现有为实心绿底白字加绿色阴影） |
| 按下 | 背景 `--bg-active` |
| 键盘焦点 | 2px 焦点环 |

激活态不用实心填充的理由：2.1.3 规则 2 规定每屏最多一个实心主按钮。3D 监测页本身没有主操作，视角切换只是浏览行为；实心填充会让左下角成为全页最醒目的元素，与模型争夺注意力。

**删除的内容**：现有 `.th-btn` 的独立边框、独立阴影、`backdrop-filter: blur(6px)`（`dashboard.html:100`）。按钮不再各自独立成块，而是合并到分段控件的外框内。

操作提示 `.th-mode-tag`（「拖拽旋转 · 滚轮缩放 · 右键平移 · 双击聚焦」）：位于视角工具条上方 8px，左对齐，`--fs-xs` / `--hud-text-muted`（含中文，不得用 11px），无底板，但加 1px 的 `--twin-clear` 文字描边保证在模型上可读。首次加载显示 6 秒后淡出（`--dur-slow`），之后仅在鼠标进入画布时显示。理由：这是新手引导信息，熟练用户不需要它常驻屏幕。

tablet 档（769–1023px）：视角组按钮文字保留（5 个视角名都是 2 个汉字，已经很短）；开关组折叠为一个「更多」按钮，点击后向上弹出菜单（下拉菜单样式，4.12）。

### 4.7 设备健康度指示器

挂载：`.health-state`（健康状态徽标，配合 `.state-online` / `.state-offline` / `.state-unknown`）、`.conn`（连接状态，配合 `.error` / `.idle`）、`.source-badge`（数据源徽标，配合 `.serial` 等）、`.dv-kv`（键值行）、`.dv-hero`（设备页连接状态主区）。

#### 4.7.1 状态映射

设备健康度属于**数据可信度**维度（`CONTEXT.md`），不属于风险等级。因此在线状态使用中性的「正常绿」只是因为绿色是全人类通用的「运转中」信号，并不代表结构风险正常。

| 状态类 | 含义 | 状态点 | 文字 | 文字颜色 |
|---|---|---|---|---|
| `.state-online` | 设备在线，数据可信 | 8px 实心 `--risk-normal-main` | 在线 | `--text-primary` |
| `.state-offline` | 设备离线，数据不可信 | 8px 空心，1px 虚线 `--trust-unknown-main` | 离线 | `--trust-unknown-text` |
| `.state-unknown` | 尚未建立连接 / 状态未知 | 8px 实心 `--trust-unknown-main` | -- | `--text-tertiary` |
| `.conn`（默认，连接正常） | 前端与后端数据通道正常 | 8px 实心 `--risk-normal-main` | 数据连接正常 | `--text-secondary` |
| `.conn`（连接中） | 正在建立连接 | 8px 实心 `--trust-unknown-main`，按 2.6.4「连接中」脉冲 | 数据连接中 | `--text-secondary` |
| `.conn.error` | 前端无法从后端取得数据 | 8px 实心 `--risk-crit-main` | 数据连接中断 | `--risk-crit-text` |
| `.conn.idle` | 空闲 / 未启用 | 8px 实心 `--trust-unknown-main` | 按页面原文 | `--text-tertiary` |

重要变化：

1. **`.state-offline` 不再使用严重报警红色**（现有 `app.css:399` 为 `--crit`）。离线是「不知道」而不是「最危险」（D7）。设备离线产生的报警记录本身是「严重报警」级别（后端规则如此），会在报警中心以严重报警徽标出现，这已经足以引起注意；健康度指示器只负责如实陈述「离线」这个状态。
2. **`.conn.error` 保留红色**：前端与后端之间的通道中断，意味着屏幕上的所有数据都已过时且用户不知道，这是一个必须立即处理的系统故障，与「设备离线」（后端知道设备离线并如实报告）在性质上不同。
3. **删除所有发光与呼吸动画**：现有 `app.css:405` 的 `ledBreath`（在线时绿灯呼吸）、`:406` 的 `ledBlink`（离线时 0.7s 闪烁）、`:193` 的 `ledBlink`（连接错误闪烁）以及所有 `box-shadow` 光晕全部删除。在线是常态，常态不应有动画（原则一）；0.7 秒的硬闪烁接近 WCAG 2.3.1 的光敏风险阈值。

#### 4.7.2 尺寸形态

| 形态 | 位置 | 规范 |
|---|---|---|
| 行内 | 顶栏连接状态、表格内、面板标题右侧 | 状态点 8px + 文字 `--fs-sm` / `--fw-medium`，间距 4px，无容器 |
| 主读数 | 设备页「连接状态」面板 `.dv-hero` 中的 `.health-state.dv-badge` | 状态点 12px + 文字 `--fs-2xl` / `--fw-semibold`，间距 8px，无容器。下方 8px 为「最近异常：」说明行（`.dv-reason`），`--fs-sm` / `--text-secondary`，异常内容 `<b>` 为 `--text-primary` / `--fw-medium` |

#### 4.7.3 数据源徽标（`.source-badge`）

| 属性 | 规范 |
|---|---|
| 尺寸 | 高 24px，水平内边距 8px，`--radius-xs` |

### 4.12 空状态、加载状态与其他通用元素

#### 4.12.1 空状态

挂载：`.empty`、`td.empty`、`.pa-empty`、`.td-none`。

| 场景 | 内容 | 规范 |
|---|---|---|
| 表格无数据（报警中心） | 「当前没有报警记录」+ 第二行「系统运行中，新报警会实时出现在这里」 | 见下 |
| 表格无数据（历史查询） | 「所选时间范围内没有记录」+ 第二行「请调整开始和结束时间后重新查询」 | 见下 |
| 图表无数据 | 「等待数据」+ 第二行「首个采样点到达后开始绘制」 | 在图表绘图区中央显示；坐标轴照常绘制（空坐标系），让用户知道图表的位置与尺度 |
| 离线导致无数据 | 「设备离线，暂无实时数据」+ 第二行「最近一次数据：{时间}」 | 第一行 `--trust-unknown-text` |

空状态通用规范：

| 属性 | 规范 |
|---|---|
| 布局 | 文字左对齐于表格或面板的内容左边缘（16px 内边距处），**不居中**；上下内边距各 48px（`--sp-12`） |
| 第一行 | `--fs-md` / `--fw-medium` / `--text-secondary` |
| 第二行 | `--fs-sm` / `--text-tertiary`，与第一行间距 4px |
| 图标 / 插图 | **不使用**。不放空箱子、放大镜、云朵等插图 |
| 操作 | 如有可执行操作（如「重新查询」），在第二行下方 12px 放一个小号次要按钮 |

左对齐而不是居中的理由：居中的空状态加插图是消费级 App 的做法；在工程界面中，空状态只是表格的一个特殊状态，文字左对齐让它与有数据时的表格内容处在同一条左边线上，状态切换时视觉位置不跳动。不放插图的理由同第六章：装饰性元素。

「当前没有报警记录」是一个**正面**状态（桥梁一切正常），但不使用绿色、对勾或庆祝式语言。理由：原则一，正常就是安静。

#### 4.12.2 加载状态

| 场景 | 形态 | 规范 |
|---|---|---|
| 页面首次加载，等待第一次数据 | 骨架屏 | 在数值、表格行、图表区域显示与真实内容同尺寸的占位块：`--bg-sunken` 底，`--radius-xs`；数值占位宽 80px 高与字号行高相同；表格占位 5 行，每行 3 个占位块（宽 30% / 50% / 15%） |
| 骨架屏动效 | 静态 | **不使用扫光动画**。理由：每秒刷新的系统，首次加载通常不超过 1 秒，扫光动画还没播完数据就到了，只会带来闪烁 |
| 查询中（历史页点击查询后） | 表格区域上方 2px 高的不确定进度条 | 宽度占满表格容器，`--bg-sunken` 轨道，`--accent-default` 滑块（宽 30%，从左到右，1200ms，`--ease-linear`，循环）；原有表格内容保留并降为 50% 透明度，直到新结果到达 |
| 按钮操作中 | 按钮加载态 | 4.8.3 |
| 3D 场景加载 | 4.6.5 | — |
| 超过 10 秒未返回 | 错误提示 | 进度条消失，表格上方显示一条警告条（4.6.5 `.warn` 样式）：「查询超时，请稍后重试」+ 右侧「重试」文字按钮 |

#### 4.12.3 模拟标识

模拟模式是原则二要求「始终可见」的状态，在多处出现，统一规范：

| 位置 | 挂载 | 规范 |
|---|---|---|
| 顶栏 | `.sh-sim-badge` | 高 24px，水平内边距 8px，`--radius-xs`；`--risk-warn-bg` 底，1px **虚线** `--risk-warn-border`，`--risk-warn-text` 文字，`--fs-xs` / `--fw-semibold`；内容「模拟数据 · 非真实硬件」；最大宽 320px（移动端只显示「模拟」） |
| 3D 监测页模拟条 | `.sim-strip`、`.demo-banner`、`.tag`、`.wm-text` | 高 48px；`--bg-surface` 背景（**删除现有琥珀底 `#fffbeb`**）；上边 1px `--border-default`；左侧 `.tag`「模拟」为徽标：高 20px，`--risk-warn-main` 底，白色（浅色主题）/ `#16181D`（深色主题）文字，`--fs-xs` / `--fw-semibold`，`--radius-xs`；`.wm-text` 为 `--fs-sm` / `--text-secondary`；右侧为场景切换分段控件（4.8.4） |

使用琥珀（预警色系）而不是新增颜色的理由：模拟模式的语义是「注意，这些数据不能当真」，与预警的「注意」同属一类提醒；使用虚线边框（与「未知」状态的虚线语言一致）进一步表达「非真实」。模拟条本身改为中性背景，是因为模拟条在演示时常驻屏幕，整条琥珀底色会让画面长期处于「警示色」笼罩下，削弱真正预警出现时的辨识度；警示信息集中在左侧的实心「模拟」徽标上。

## 五、页面级设计

### 5.0 页面如何共享设计系统

七个页面之间的差异**只允许来自内容与布局**。具体约束如下，任何页面都不得例外：

| 层 | 归属 | 页面内联 `<style>` 允许写什么 |
|---|---|---|
| Token（颜色、字号、间距、圆角、阴影、时长） | 全局 token 文件（第八章 8.3） | 不允许写任何 token 字面量；只能引用变量 |
| 骨架（侧栏、顶栏、内容区、栅格） | `_shell.html` 内联块 | 不允许覆盖骨架样式 |
| 组件（第四章的 12 类组件） | 全局组件样式 | 不允许改组件的颜色、字号、圆角、阴影、内边距 |
| 页面布局 | 页面内联 `<style>` | 只允许：区域的栅格列跨度、区域的固定高度（如图表高度）、区域的排列顺序 |

各页面现有的前缀类（`.pg-*` 实时趋势、`.pa-*` 报警中心、`.dv-*` 设备、`.his-*` / `.filters` 历史、`.set-*` 设置、`.hero-*` / `.ms-*` 3D 监测）保留，但只承担上表最后一行的职责。现有写在这些前缀类上的颜色（如 `alarms.html:63` 的 `#6b7280`、`alarms.html` 中 `.pa-glyph` 的 `#16a34a`）、字号（如 `calc(12.5px * var(--pg-s))`）全部删除，改由组件样式提供。

页面共有的固定结构（自上而下）：

1. 顶栏：页面标题 + 副标题 + 全局状态区（3D 监测页为 `.hero-top`）。
2. 内容区第一行：本页的指标卡行（如有）。
3. 内容区主体：本页的主面板。
4. 页脚行（如有）：单位口径、最近刷新时间。`--fs-xs` / `--text-tertiary`，距上方面板 16px，左对齐。

**每页只有一个主角**。下表规定每页最重要的元素，它获得该页最大的面积、唯一的 `--fs-3xl`、或唯一的主按钮：

| 页面 | 主角 | 用户来这一页要回答的问题 |
|---|---|---|
| 登录 | 登录表单 | 我能进入系统吗？ |
| 3D 监测 | 3D 桥体模型 + 风险等级 | 桥现在安全吗？哪里出了问题？ |
| 实时趋势 | 趋势主图 | 应变在怎样变化？离阈值还有多远？ |
| 报警中心 | 报警处置队列 | 有哪些报警需要我处理？ |
| 历史与导出 | 查询结果（表格或图表） | 过去某段时间发生了什么？ |
| 设备与数据源 | 连接状态 | 数据是从哪里来的？可信吗？ |
| 系统设置 | 监测参数表单 | 判定规则的参数是什么？要不要调？ |

**为什么不居中**：水平垂直居中的登录框配一个大背景图，是第六章禁止的「landing page 式布局」的变体。偏左上的定位来自瑞士平面设计的不对称版式：内容沿网格的一条竖线对齐，而不是漂浮在画面正中，传达的是「这是一个工具的入口」而不是「这是一个产品的展示页」。1/6 和 1/4 这两个比例让表单处于视线自然落点（左上象限），同时与登录后页面的内容左边缘（侧栏 240px + 内边距 24px，在 1920px 宽屏上约为 1/7 处）大致呼应，登录前后的视觉重心不会跳跃。

**为什么右侧留空**：登录页的使用者是已经知道这个系统是什么的工程人员。任何宣传性内容都是噪音。空白本身就是「克制」最直接的表达。

**为什么不显示主题切换**：登录页是一次性的过渡页面，主题切换入口在登录后的侧栏底部。

#### 5.1.3 状态

| 状态 | 表现 |
|---|---|
| 默认 | 用户名输入框自动获得焦点 |
| 提交中 | 登录按钮进入加载态（4.8.3）；两个输入框变为只读 |
| 凭据错误 | 错误提示出现在登录按钮上方（4.10.4），内容「用户名或密码错误」；密码框清空并获得焦点；用户名保留 |

**画布外没有任何面板**。按 D3，仪表盘、趋势曲线、报警队列不出现在本页。用户需要这些信息时，从侧栏进入实时趋势或报警中心。本页回答的唯一问题是「桥现在安全吗、哪里出了问题」，而这个问题由「风险等级 + 测点颜色 + 测点标签上的读数」完整回答。

**风险等级与当前应变指标是全页仅有的两个 32px 元素**。它们位于指标带左侧（视线起点），风险等级在最左。理由：值班人员走过屏幕时，第一眼要看到的是「严重报警」四个字，第二眼才是具体数字。

**严重报警时页面怎么变化**：

| 元素 | 变化 |
|---|---|
| 指标带风险等级单元格 | 左侧 4px `--risk-crit-main` 色条；状态点 12px 红色，未处理时脉冲；文字「严重报警」`--risk-crit-text` |

| 测点标签 | 状态点变红并脉冲；边框变为 `--risk-crit-border` |
| 图例 | 「严重报警」项加粗 |
| 侧栏「报警中心」 | 显示红色计数徽标 |
| 顶栏通知铃 | 红点脉冲 |
| **不变的** | 页面背景、指标带底板、画布背景、工具栏、其他数值的颜色 |

#### 5.5.2 关键决策

**「历史数据比对」的统计指标不用独立卡片**：5 个统计值（平均、最大、最小、超限次数、后半段对比）是对同一条曲线的描述，它们与曲线是一个整体。放在同一个面板里、用分隔线而不是独立卡片隔开，表达的是「这些数字属于下面这张图」。现有实现是 5 个独立 `.stat` 块加一个独立图表卡片，两者在视觉上是分离的。

**超限次数的标签**「超限次数 (>{阈值})」：括号与阈值使用 `--font-data`；当超限次数大于 0 时，数值右侧加 8px 的 `--risk-alarm-main` 状态点（不改变数值颜色）。

**「后半段 vs 前半段均值」**：数值带符号（`+3.21%`），趋势指示规则同 4.1.1（不使用红绿）。

**标签页切换不清空查询条件**：两个标签共用同一组开始/结束时间（现有行为），切换时保留。

## 六、避免「AI 味」

### 6.1 什么是「AI 味」，为什么在这里格外有害

「AI 味」指的是一组被大量生成式工具与模板重复使用、因而失去了信息含义的视觉套路。它们的共同特征是：**装饰先于内容，情绪先于信息**。看到蓝紫渐变加毛玻璃，用户不会想到「这是一个精确的监测系统」，只会想到「这又是一个模板生成的大屏」。

在桥梁监测场景中，这种观感的代价比普通产品更高：

1. **信任成本**。监测系统的价值完全建立在「它说的是真的」之上。廉价的视觉套路会让工程人员、评审专家、业主下意识地怀疑数据本身也是「做出来的效果」。
2. **注意力成本**。装饰性的动效、光晕、渐变会持续消耗值班人员的注意力，真正的报警出现时反而不够突出（原则一）。
3. **辨识成本**。发光和渐变会改变颜色的感知亮度，让风险色的判读变得不可靠：一个带红色外发光的橙色元素，看起来到底是报警还是严重报警？

本章列出的每一条禁止项，都附有它在当前代码中的实际存在情况，以及替代做法。**实现者在完成任何一个页面后，都应逐条对照 6.4 的自检清单。**

### 6.3 禁止项与替代方向

每一条禁止项按「禁止什么 / 为什么 / 改用什么」组织。

#### 1. 紫、蓝、粉多色渐变

- **禁止**：任何两种以上色相之间的渐变，尤其是紫到蓝、蓝到青、紫到粉。包括背景、按钮、文字、边框、图表填充、3D 环境贴图。
- **为什么**：这是生成式工具最常见的默认色，已经成为「AI 生成」的视觉标志。它不表达任何信息。
- **改用**：中性灰阶加单一钢蓝强调色（2.1.3）。需要表达「从低到高」的连续量时（如仪表盘色带），使用离散的分段色块，不使用连续渐变。

#### 2. 任何形式的装饰性渐变

- **禁止**：即使是同色相的明暗渐变，也不得用于面板背景、按钮、图表面积填充、页面背景、标题栏。
- **为什么**：渐变会让同一个元素的不同位置呈现不同颜色，削弱颜色作为语义信号的确定性；同时它是「立体感、质感」的装饰手法，与「平面、精确」的工程图纸气质相反。
- **改用**：纯色。图表面积填充为 6% 透明度的纯色（2.1.6 `--chart-area`）。
- **唯一例外**：3D 场景的程序化环境贴图内部需要天空到地平线的明度过渡来产生可信的金属反射（第七章）。这是渲染物理需要，不是界面装饰，并且用户看到的只是反射结果，不是渐变本身。

#### 3. 玻璃拟态（毛玻璃）

- **禁止**：`backdrop-filter: blur()`，以及任何「半透明白底 + 模糊 + 细白边」的卡片样式。
- **为什么**：毛玻璃是近年「科技感大屏」的标准配置，背后的内容透过来会降低文字对比度且使其不稳定（背后是什么颜色，文字对比度就是多少）；在 WebGL 画布上做模糊还会显著拉低帧率。
- **改用**：实色面板。3D HUD 使用 92% 不透明的 `--hud-bg`，不加模糊（2.1.7）。

#### 4. 霓虹发光与外发光

- **禁止**：`box-shadow` 的扩散发光（偏移为 0、模糊半径大于 0 的彩色阴影）、`text-shadow` 发光、`filter: drop-shadow` 彩色光晕、SVG 发光滤镜、3D 中的泛光（bloom）后处理。
- **为什么**：发光会改变颜色的感知亮度和面积，让「这个点是什么等级」的判读变得不可靠；在近黑背景上大量发光就是第六章要禁止的「赛博朋克大屏」。
- **改用**：靠颜色本身的对比度（2.1.4 已实算全部达标）、形态差异（色条宽度、实心与描边）、以及唯一允许的状态点脉冲来表达强调。

#### 5. 用 emoji 和装饰符号当图标

- **禁止**：界面中任何 emoji（`U+26D4`（禁止通行符号） `U+26A0`（警告符号） `U+1F514`（铃铛） `U+2705`（勾选框） 等）；在文案前加 `U+26A0`（警告符号）、`U+2713`（对勾）、`U+2715`（叉号）、`●`、`▲` 等符号字符充当图标。
- **为什么**：emoji 在不同操作系统上外观完全不同（Windows 与 Mac 的 `U+26D4`（禁止通行符号） 颜色、形状都不一样），无法控制颜色、无法跟随主题，并且带有强烈的「聊天软件」语气。符号字符的大小、基线随字体变化，无法与文字精确对齐。
- **改用**：内联 SVG 线性图标，单色 `currentColor`，描边 1.5px，尺寸按 4.8.2 与 4.9 规定（14 / 16 / 18 / 20px）。现有 `_shell.html` 已建立的内联 SVG 图标体系（`icon()` 宏）是正确的做法，全站统一使用它。状态点用 CSS 绘制。文案中带警告符号前缀的「数据连接失败」去掉符号，改为「数据连接失败」，警示含义由所在组件（错误提示条）的颜色和图标承担。

#### 6. 居中大标题加副标题加按钮的落地页布局

- **禁止**：页面或区块以「水平居中的超大标题 + 一行灰色副标题 + 一两个按钮」开头；登录页水平垂直居中的卡片加大背景图；空状态居中插图加居中文字。
- **为什么**：这是营销落地页的版式，目的是「吸引注意、引导转化」。监测系统的页面是工作台，用户已经在这里了，不需要被吸引。
- **改用**：全部内容左对齐于栅格（原则三）。页面标题在顶栏左侧、20px；登录表单偏左上（5.1）；空状态左对齐、无插图（4.12.1）。

#### 7. 无意义的装饰性背景

- **禁止**：粒子、星点、光斑、网格底纹、点阵、扫描线、电路板纹理、等高线、模糊色块（「光晕球」）、噪点纹理，无论静态还是动态。
- **为什么**：它们不传达任何信息，却持续占用视觉注意力，并降低前景文字的对比度。现有 `--grid: rgba(224, 185, 123, .05)` 网格底纹、`#fx-layer` 粒子层与扫描带均属此类。
- **改用**：纯色背景（`--bg-canvas`）。层次由背景层级和发丝边建立（2.1.1、2.1.8）。
- **唯一例外**：「未知」状态的 45° 斜线纹理（2.1.4）。它是有语义的图案，表达「数据不可信」，且只出现在 4px 宽的色条和小面积指示器上。

#### 8. 所有卡片相同圆角、相同阴影、相同悬停浮起

- **禁止**：全站统一 8px 或 12px 圆角；每张卡片都有投影；悬停时卡片上浮并加深阴影。
- **为什么**：统一的「圆角卡片 + 阴影」会让整个界面变成一堆漂浮的气泡，没有结构；悬停浮起暗示可点击，误导用户。
- **改用**：圆角按尺寸分级（2.4）；常规面板无阴影，只有浮层有阴影（2.5）；悬停只改颜色（2.6.3）。

#### 9. 彩虹色或渐变文字

- **禁止**：渐变填充的文字（背景裁剪到文字）、多色标题、发光标题、描边空心大字。
- **为什么**：文字的职责是被阅读。渐变文字降低可读性，并且是 AI 生成标题的典型特征。
- **改用**：标题一律 `--text-primary` 纯色。层级靠字号与字重（2.2.2、2.2.3），不靠颜色。

#### 10. 蓝紫背景加半透明卡片的「科技感」组合

- **禁止**：深蓝或深紫的页面背景（如 `#0a0e27`、`#1a1040` 这类带明显色相的深色）加半透明卡片、青色描边、角标装饰（卡片四角的 L 形线条）、六边形元素、斜切角卡片。
- **为什么**：这是「智慧城市指挥大屏」的标准套路，正是本规范 1.3 气质坐标中明确排除的参照物。
- **改用**：深色主题使用近乎中性的深灰（`#0B0C0E`、`#121316`，冷调偏差人眼不可察觉，2.1.8 第 5 条）；卡片实色、直边、1px 发丝边。
- 说明：上文第 4 条禁止 `text-shadow`，唯一例外是 3D 画布上无底板的操作提示文字（4.6.1 `.th-mode-tag`）所使用的 1px `--twin-clear` 色文字描边。它的颜色与画布背景相同，作用是保证文字在模型前可读，而不是发光，因此不属于装饰。

#### 11. 装饰性动效

- **禁止**：页面加载时面板逐个飞入或淡入；数字从 0 滚动到目标值；悬停时元素放大、旋转、弹跳；持续循环的呼吸、闪烁、流动、旋转效果（2.6.4 允许的三种除外）。
- **为什么**：动效应当解释状态的变化，而不是制造「活力」。数字滚动还会显示从未测到过的虚假数值（2.6.3）。
- **改用**：2.6 动效系统。默认没有动画，只有颜色过渡。

#### 12. 字母间距拉开的英文大写装饰标签

- **禁止**：作为纯装饰的英文大写小标签，如在中文标题上方放一行 `REAL-TIME MONITORING`、`SYSTEM STATUS`，并拉开字距。
- **为什么**：这是模板中常见的「增加设计感」手法，中文界面加英文装饰标签不提供任何信息。
- **改用**：删除。保留的英文只有产品名「Bridge Guardian」（侧栏副标、登录页页脚）与技术标识（`ESP32`、`CH1`）。登录页页脚的「BRIDGE GUARDIAN · STRUCTURAL HEALTH MONITORING」作为产品署名保留，但它位于页面最底部、11px、`--text-tertiary`，不是装饰性标题。

#### 13. 用颜色表达非语义信息

- **禁止**：给不同的导航项、不同的指标卡、不同的面板分配不同的颜色以「区分」它们；给图标上色；用强调色做标题、做装饰色条。
- **为什么**：颜色已经被风险等级和交互状态占用（原则一）。多出来的颜色会被用户误读为状态。
- **改用**：区分靠文字、位置和线型。图标一律 `currentColor`，跟随文字颜色。

## 七、3D 场景视觉整合

### 7.1 总体定位

3D 场景的视觉目标是**一张会动的工程模型照片**，而不是一段游戏过场动画。具体来说：

- 桥体是中性灰的钢与混凝土，像一个做工精良的缩尺物理模型放在均匀光照的展台上。
- 场景中唯一的饱和色是测点（以及风险升级时受影响的吊索），它们是数据，不是装饰。
- 场景与页面是一体的：画布背景与页面背景同色，没有「一个发光的窗口嵌在页面里」的感觉。

现有 3D 引擎（`static/js/twin/`）的浅色主题已经基本符合这一定位，P2 在浅色渲染上做的明度阶梯（`theme.js` 头注释）是正确的基础，**本章保留其结构，只调整颜色取值与少量动效**。深色主题仍是 P1 之前的「黑曜石 + 香槟金」配方，需要按本章改为中性冷灰，与第二章深色 token 对齐。

本章不改变：几何建模、相机控制方式、5 个预设视角、画质分档（`quality.js`）、帧率治理机制、测点数量与位置。

### 7.2 颜色来源：CSS token 是唯一真相

现状：3D 的颜色写死在 `theme.js`（如 `RISK_COLORS_LIGHT`、`clear: 0xf2f5f7`），页面 CSS 中又有一份（`dashboard.html:44` 的 `--twin-clear`），两处靠注释约定「必须同值」。

规范：

1. 第二章的 CSS 变量是唯一真相。3D 场景挂载时（`mount.js`）以及每次主题切换后，从根元素计算样式中读取 7.2 表中的变量，作为参数传给场景（场景已有的 `setTheme` 接口扩展为同时接收这组颜色）。
2. `theme.js` 中对应字段保留，但其值改为与 CSS 变量**完全相同的字面量**，仅作为读取失败时的兜底。
3. 3D 场景从 CSS 读取的变量清单：

| CSS 变量 | 3D 中的用途 | 现有 `theme.js` 字段 |
|---|---|---|
| `--twin-clear`（= `--bg-canvas`） | 渲染器清屏色；雾色 | `clear`、`fog.color` |
| `--risk-normal-main` | 测点（正常） | `RISK_COLORS_*.normal` |
| `--risk-warn-main` | 测点、吊索（预警） | `RISK_COLORS_*.warn` |
| `--risk-alarm-main` | 测点、吊索（报警） | `RISK_COLORS_*.alarm` |
| `--risk-crit-main` | 测点、吊索（严重报警） | `RISK_COLORS_*.crit` |
| `--trust-unknown-main` | 测点（离线） | `RISK_COLORS_*.offline` |
| `--accent-default` | 被选中测点的选中环 | 无（新增） |
| `--text-secondary` | 结构线框模式的线色 | `wire.color` |

取值结果：

| 字段 | 浅色现值 → 新值 | 深色现值 → 新值 |
|---|---|---|
| 清屏色 | `#f2f5f7` → `#F4F5F7` | `#070708` → `#0B0C0E` |
| 雾色 | `#dfe6ea` → `#F4F5F7` | `#0e0d0c` → `#0B0C0E` |
| 正常 | `#15803d` → `#2F855A` | `#e0b97b` → `#4CB782` |
| 预警 | `#b45309` → `#B7791F` | `#fbbf24` → `#E0A82E` |
| 报警 | `#c2410c` → `#C25A16` | `#fb923c` → `#E87A3A` |
| 严重报警 | `#be123c` → `#C8353B` | `#f43f5e` → `#EF5A5F` |
| 离线 | `#6b7280` → `#8A9099` | `#77716a` → `#6B7079` |
| 线框 | `#334155` → `#4B515A` | `#e0b97b` → `#B4B8BF` |

**雾色改为与清屏色相同**的理由：现有浅色主题雾色 `#dfe6ea` 比背景 `#f2f5f7` 暗，远处的峡谷会收敛到一个比页面背景更深的灰色，在画面远端形成一条可见的「地平线色带」，画布边缘看起来像一个窗口。雾色等于背景色后，远景自然溶解进页面背景，3D 场景与页面没有边界，符合 7.1 第 3 条。

**深色主题的正常色不再是香槟金**：这是 0.3 第 1 条在 3D 中的对应修复。

### 7.3 背景、环境光与雾

#### 7.3.1 背景

- 画布背景为纯色 `--twin-clear`，不使用天空盒、渐变背景、星空、HDR 环境背景图。
- 环境贴图（程序化 equirect 渐变，用于金属与玻璃的反射）只参与材质反射计算，**不作为可见背景**（现有实现如此，保持）。

#### 7.3.2 光照

浅色主题光照保持现值（`theme.js` `THEME_LIGHT.lights`），已经是中性冷白光。

深色主题光照调整：

| 光源 | 现值 | 新值 | 理由 |
|---|---|---|---|
| 半球光 天空色 / 地面色 / 强度 | `#b5b9bd` / `#121110` / 0.55 | `#B4BAC2` / `#101113` / 0.55 | 地面色去掉暖调 |
| 主光 颜色 / 强度 | `#f5f2ec` / 1.12 | `#F2F4F7` / 1.12 | 去掉暖调，改为中性略冷的白光 |
| 轮廓光 颜色 / 强度 | `#e0b97b`（香槟金）/ 0.75 | `#C8CED6` / 0.45 | 金色轮廓光是「黑金质感」的主要来源，属于装饰性氛围光；改为中性冷灰并降低强度，只保留帮助桥体轮廓从深色背景中分离的功能 |
| 环境光 颜色 / 强度 | `#1e1e20` / 0.30 | `#1C1E22` / 0.30 | 对齐 `--bg-raised` |

主光方向两套主题一致（现有 `pos: [-900, 1500, -1200]`），保持不变：光从左后上方来，与 HUD 的阴影方向（向下）不冲突。

| 1.00 谷底 | `#040405` | `#060708` |
| 太阳光斑 内圈 | `rgba(255,250,242,0.62)` | `rgba(242,244,247,0.55)` |
| 太阳光斑 中圈 | `rgba(210,180,130,0.18)`（金色） | `rgba(180,186,194,0.14)` |

理由：地平线金色亮带会在所有金属构件（主缆、钢桁梁、索夹）上反射出一条金色高光，使整座桥呈现「黑金」质感。改为中性灰后，金属的反射仍然存在（体积感保留），但不再带有装饰性色调。

这是 6.3 第 2 条「禁止渐变」的唯一例外：环境贴图渐变是渲染物理的需要，用户看不到渐变本身，只看到它在材质上的反射。

#### 7.3.4 雾

- 雾色等于清屏色（7.2）。
- 雾密度保持现值（浅色 0.00016，深色 0.00019）。
- 峡谷薄雾层（`mist`，低画质档已关闭）：

| 主题 | 现值 | 新值 | 理由 |
|---|---|---|---|
| 浅色 | 白色，普通混合，不透明度 0.06 | 保持 | — |
| 深色 | `#ebdcc1`（暖米色），**叠加混合**（additive），不透明度 0.055 | `#9AA1A9`，**普通混合**，不透明度 0.05 | 叠加混合会让雾层在深色背景上发光，属于 6.3 第 4 条禁止的发光效果；暖米色同样是黑金配方的一部分 |

薄雾的横向漂移（`scene.js:1075`，周期 14 秒以上的缓慢平移）保留：它周期极长、幅度极小，作用是让峡谷有空气感，不会被感知为「动画」。减弱动效时停止。

### 7.4 材质色调

#### 7.4.1 原则

结构材质只使用中性灰，**材质本身不随风险等级变色**。明度阶梯沿用 P2 的四层（`theme.js` 头注释）：深灰钢构 → 中性灰混凝土 → 金属高光的缆索 → 风险色测点。

#### 7.4.2 浅色主题

全部保持现值（`MATERIAL_THEMES.light`），只调整一处：

| 配方 | 现值 | 新值 | 理由 |
|---|---|---|---|
| `glass`（观景平台玻璃） | `#cdd8de`，不透明度 0.34 | `#D5DAE0`，不透明度 0.30 | 现值偏蓝，降低色相，与中性灰体系一致 |

#### 7.4.3 深色主题

|---|---|---|---|
| `steel` 钢桁梁 | `#b9b7b4` | `#A9AEB4` | 去暖调；略降明度，避免在近黑背景上过亮刺眼 |

| `road` 沥青 | `#10100f` | `#16181B` | 比清屏色略亮，保证桥面在俯视角下不与背景融为一体 |

#### 7.4.4 风险色作用于哪些构件

现有实现把风险色（`PALETTE.accent` / `bright` / `dim`）作用到大量构件上：车道发光条 `laneGlow`、栏杆发光条 `railGlow`、各类描边 `edge` / `glassEdge` / `concreteEdge`、主缆流光 `cableFlow`、塔顶信号灯 `beacon`、线框、吊索。正常状态下整座桥都带有正常色（深色主题下即香槟金）的描边与发光条。

这违反原则一。新规则：

| 构件 | 正常 | 预警 / 报警 / 严重报警 | 离线 | 理由 |
|---|---|---|---|---|
| 测点核心球 + 涟漪环 | 对应风险色 | 对应风险色 | `--trust-unknown-main` | 测点是数据，始终显示状态 |
| 吊索（按荷载着色，现有 `maybeApplyRisk`） | 材质中性色 `cable` | 荷载超过阈值的吊索使用当前风险色；其余保持中性 | 中性 | 只有「受力异常」的构件变色，帮助定位问题位置 |
| 结构线框（「结构线框」开关开启时） | `--text-secondary` | `--text-secondary`（**不随风险变色**） | `--text-secondary` | 线框是结构透视工具，不是状态指示 |
| 构件描边 `edge` / `glassEdge` / `concreteEdge` | 材质色加深 15%（中性） | 同左 | 同左 | 描边只用于强化形体轮廓 |
| 车道发光条 `laneGlow`、栏杆发光条 `railGlow` | 改为非发光的中性材质：浅色 `#C8CCD2`，深色 `#4E525A` | 同左 | 同左 | 「发光条」是装饰；作为桥面标线保留几何，去掉发光与风险色 |
| 主缆流光 `cableFlow`（缆索上流动的光带） | **删除**（或在所有画质档关闭） | 同左 | 同左 | 流动光带是典型的赛博装饰（6.3 第 7、11 条），且不对应任何真实物理量 |
| 塔顶信号灯 `beacon` | 中性 `--text-tertiary` 色，不发光、不闪烁 | 同左 | 同左 | 若它代表真实的航空障碍灯，应为固定的红色；但红色会与严重报警混淆，故改为中性，仅保留几何 |

吊索变色阈值：以吊索所在区段对应测点的荷载比（应变 / 阈值）判定，与 4.4.3 仪表色带相同的分界：1.0 / 1.1 / 1.2 倍。荷载比 ≤1.0 的吊索保持中性。现有实现按荷载连续着色，改为按上述三档离散着色。理由：连续色阶会在「正常但接近阈值」时让吊索呈现介于中性与琥珀之间的模糊颜色，用户无法判断是否已经越过预警线；离散着色与全站四级风险口径一致。

风险等级变化时的颜色过渡：现有 `lerpPalette` 按每帧逼近目标色（约 300 到 400ms 收敛），与 `--dur-slow`（400ms）一致，保留。主题切换时直接对齐、不过渡（现有 `opts.snap`），保留，与 2.6.3「主题切换无过渡」一致。

### 7.5 测点与涟漪节奏

#### 7.5.1 测点几何

保持现有几何（核心球 + 竖杆 + 面向相机的涟漪环）。调整：

| 元素 | 现状 | 新规范 |
|---|---|---|
| 核心球 | 随 `sin(pulse × 6π)` 持续缩放抖动（`scene.js:1057`，幅度 ±12%） | **静止**，不缩放。理由：核心球是测点的「位置」，位置标记不应该抖动；节奏由涟漪表达即可 |
| 涟漪环 | 面向相机的圆环，从 3.2 倍扩散到 15.2 倍，不透明度 0.5 → 0 | 扩散范围与淡出方式保持，节奏与数量按 7.5.2 |
| 测点光晕 `sensorHalo` | 浅色普通混合 0.22；深色叠加混合 | 两套主题都使用**普通混合**；不透明度 0.20 |
| 被选中的测点 | 无专门表现 | 核心球外增加一个静止的细圆环：半径为核心球的 2.2 倍，线宽相当于屏幕 1.5px，`--accent-default` 色，不透明度 1.0，面向相机。这是 3D 中唯一使用强调色的地方，表达「当前选中」这一交互状态 |

#### 7.5.2 涟漪节奏

涟漪节奏是 3D 场景中风险等级的**时间维度编码**。

| 风险等级 | 周期（一次扩散） | 现有速率 | 同时存在的环数 | 环的最大不透明度 | 核心尺寸系数（现有 `scaleBase`） |
|---|---|---|---|---|---|
| 正常 | 4000ms | 0.6 次/秒 | 1 | 0.20 | 1.0 |
| 预警 | 2400ms | 0.85 次/秒 | 1 | 0.35 | 1.0 |
| 报警 | 1600ms | 1.25 次/秒 | 2（相位差 50%） | 0.45 | 1.0 |
| 严重报警 | 1000ms | 1.9 次/秒 | 2（相位差 50%） | 0.55 | 1.0 |
| 离线 | 不扩散 | 0 | 0（全部隐藏） | — | 0.55（现有值，保留） |

调整说明：

1. **正常态放慢到 4 秒一次，且不透明度降到 0.20**。正常态的涟漪保留，作用是「数据在流动」的心跳信号：它与离线时涟漪完全消失形成对比，用户一眼就能分辨「正常」与「断线」。但它必须足够安静，不能吸引注意（原则一）。
2. **严重报警从 1.9 次/秒放慢到 1 次/秒**。双环相位差 50%，所以视觉上每 500ms 出现一个新环，即每秒 2 次，低于 WCAG 2.3.1 的每秒 3 次闪烁上限，留有余量。现有 1.9 次/秒在双环叠加时接近每秒 4 次，已超出上限。
3. **严重报警的核心尺寸系数从 0.85 改为 1.0**。现有实现让严重报警时测点变小（`scene.js:770`），意图是「节奏更紧凑」，但会让最危险的测点在画面中更难被找到。
4. 离线时涟漪全部隐藏（现有为不透明度降到 15% 继续存在），核心球显示 `--trust-unknown-main`，不透明度 0.6。理由：残留的淡环容易被误读为「还在工作」。

#### 7.5.3 减弱动效

`prefers-reduced-motion: reduce` 时：涟漪不扩散，每个测点显示一个静止的环（半径为最大扩散半径的 40%，不透明度按上表最大值）；不同等级通过环的颜色和不透明度区分。薄雾漂移、水面漂移、自动旋转全部停止；视角切换瞬间完成。

### 7.6 HUD 与 3D 场景的协调

第四章 4.6 规定了 HUD 各元素本身的样式。本节规定它们与 3D 场景的空间关系。

#### 7.6.1 取景安全区

画布四周被 HUD 占用的区域称为 HUD 带，3D 相机取景时必须避开它们：

| 边 | HUD 带宽度 | 构成 |
|---|---|---|
| 上 | 120px | 指标带 16px 外距 + 88px + 16px 间隙 |
| 下 | 64px | 视角工具条 32px + 16px 外距 + 16px 间隙 |
| 左 | 16px | 外距 |
| 右 | 16px | 外距（测点详情打开时为 312px，但详情是临时浮层，取景不避让） |

5 个预设视角的取景（`viewPresets` 的 `spanW` / `spanH` 与 `fitDistance()`）必须以**扣除 HUD 带后的矩形**作为可视区计算相机距离，并让模型中心落在该矩形的中心，而不是整个画布的中心。实现上可通过相机的视图偏移把投影中心下移 28px（(120 − 64) / 2），同时用安全区高度代替画布高度参与 `fitDistance()` 的计算。

理由：现有取景以整个画布为准，桥体上部（主缆、塔顶）会被指标带遮挡，尤其是「全桥」和「桥塔」两个视角。

tablet 档指标带为两行（152px）时，上 HUD 带相应变为 184px。全屏观看模式下指标带隐藏，上 HUD 带变为 16px（模拟模式下为 56px，容纳左上角模拟标识）。

#### 7.6.2 HUD 不遮挡数据

- 测点标签（4.6.3）与 HUD 固定元素（指标带、工具条、图例）重叠时，测点标签让位：标签向远离 HUD 的方向偏移，直到不重叠；引线保持指向测点。如果偏移后仍会超出安全区，标签隐藏，只保留测点本身。
- 测点详情（4.6.4）打开时会覆盖画布右上区域，此时被覆盖的测点标签降为 40% 不透明度，不隐藏。
- 任何 HUD 元素都不得覆盖「当前风险等级最高的测点」：当该测点的屏幕位置落入测点详情面板范围内时，详情面板改到画布左上（指标带下方 16px、左 16px）显示。

#### 7.6.3 视觉分层

自后向前：3D 场景（含雾）→ 测点标签层 → HUD 固定元素层 → 测点详情 → 悬浮提示。对应 2.5.2 的 z-index 变量。

HUD 元素与 3D 场景的视觉区分只依赖三件事：92% 不透明底板、1px 边框、`--shadow-sm`。不使用模糊、发光、彩色边框、半透明渐变边缘。

#### 7.6.4 鼠标交互的视觉反馈

| 交互 | 反馈 |
|---|---|
| 悬停测点 | 光标变为手型；该测点的标签边框变为 `--border-strong`；不改变测点本身 |
| 点击测点 | 显示选中环（7.5.1）与测点详情（4.6.4） |
| 双击测点 | 相机飞近（现有功能），过渡时长 600ms，`--ease-standard` 对应的三次曲线；减弱动效时瞬间完成 |
| 拖拽旋转 / 平移 / 滚轮缩放 | 无额外视觉反馈；`.th-mode-tag` 在交互开始时隐藏 |
| 切换预设视角 | 相机过渡 600ms；视角组按钮立即切换激活态，不等相机到位 |

相机过渡用 600ms 而不是 2.6.1 的上限 400ms：3D 相机移动的距离可达数百米，400ms 内完成会让用户失去空间方位感。这是动效系统中唯一超过 400ms 的过渡，仅限 3D 相机。

### 7.7 主题切换时的 3D 行为

1. 用户在侧栏点击主题切换后：根元素 `data-theme` 立即改变 → 页面 CSS 立即生效 → 3D 场景读取新的 CSS 变量并调用 `setTheme`，场景颜色、光照、环境贴图、雾、材质一次性切换（现有实现不重建几何，保留）。
2. 页面与 3D 的切换必须在同一帧内完成。若 3D 切换需要重建环境贴图而耗时，先同步切换清屏色和雾色（保证画布边缘与页面背景无缝），再异步完成其余部分。
3. 主题选择存储在 `localStorage['bg.theme']`（新增键，与现有 `bg.sidebar.collapsed` 命名一致），取值 `light` / `dark`；页面加载时在 `<head>` 中同步读取并设置 `data-theme`，避免先显示浅色再闪成深色。3D 场景创建时直接使用该主题，不先以浅色创建再切换。

### 7.8 性能约束

视觉调整不得引入新的渲染开销：

- 不新增后处理（泛光、景深、环境光遮蔽、描边后处理）。
- 不新增透明材质；删除主缆流光反而减少了一层透明绘制。
- 被选中测点的选中环使用与涟漪环相同的几何与材质类型。
- 测点标签避让（7.6.2）在相机移动时计算，相机静止时不计算；计算频率不超过每帧一次，并复用现有 `updateLabels()` 的调用时机。
- 画质分档（`quality.js`）的四档逻辑不变；薄雾在低画质档关闭的现有行为保留。

### 8.2 类名约定

#### 8.2.1 总规则

1. **现有类名、ID、`data-*` 属性全部保留**（D6）。它们是 JS 与测试的契约。本规范所有组件规范都挂在现有类名上。

#### 8.2.3 状态点与色条的统一实现方式

全站有大量「按风险等级显示不同颜色」的元素。为避免每个组件各写一遍五态颜色，规定：

- 颜色的唯一来源是 `data-risk` 属性。组件根元素（或状态点、色条自身）带 `data-risk`，CSS 通过属性选择器把 `--risk-*` 系列映射到一组组件内部变量（如「当前状态的 main / bg / text / border」），组件内部只引用这组内部变量。
- 这样新增任何带风险色的组件时，只需加 `data-risk`，不需要再写五条颜色规则。
- 现有用类名表达等级的写法（`.risk-card.risk-crit`、`.dl-item.warn`、`.tier.ok`、`.state-online`）保留类名，但在样式中统一映射到上述内部变量，不再各自写死颜色。
